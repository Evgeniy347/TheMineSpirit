## Тестирование в масштабе (нужен выбор стека)

Цель: тысячи осмысленных тестов, уложенные в минуту, не замедляя основной прогон. Core уже без Minecraft —
это то, что позволяет держать тесты быстрыми. Остаётся способ генерации количества.

- [x] Генератор: `jqwik` 1.10.2 (JUnit Platform 1.14.4). Правила — docs/TESTING.md → «Property-based тесты».
- [x] `.jqwik-database` в `.gitignore`; `jqwik.tries.default=1000`; быстрый тир ~1 c (бюджет ~60 c).
- [ ] Data-driven таблицы: валидатор плана, каталог, сериализация наблюдения — сотни кейсов из одной таблицы.
- [ ] Property-based инварианты core: стабильность hash, round-trip JSON, парсер плана не бросает ничего кроме
      `PlanValidationException`.
- [ ] Детерминированный in-memory харнесс «фейковый мир» для движка; сценарии задаются параметризацией.
- [ ] Параллельный прогон JUnit (`junit-platform.properties`) + forking; бюджет быстрого тира ~1 мин.
- [ ] Теги `fast`/`slow`: `./gradlew test` — быстрый тир, тяжёлое и GameTest — отдельными задачами.
- [ ] Покрытие (JaCoCo) — индикатор и отчёт, не гейт сборки (гейт — сторожа и тесты).
