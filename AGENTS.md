## Исполнитель (opencode)

Код пишет opencode, задания ставит и проверяет главный агент (см. docs/LEAD-AGENT.md).

- Ты работаешь без собеседника: вопросы пользователю недоступны. Решай сам по этим правилам.
  Если часть задания требует решения пользователя (версии, публикация, перезапуск сервера, мир игроков),
  не делай эту часть и назови её в отчёте.
- Тесты — ТОЛЬКО через `scripts/test.sh` (`unit` / `gametest`): полный лог пишется в `TestResults/logs/`, на экран — итог.
  Не перезапускай ради лога. По ходу работы — точечно: `scripts/test.sh unit --tests <свои классы>`. Полный `scripts/test.sh unit`
  перед каждым коммитом с правками `src/` запускает хук `pre-commit` — сам его не повторяй. GameTest — только после
  правки GameTest или кода, работающего с миром, не чаще раза на пункт; полный прогон GameTest — в финале ветки
  (docs/GIT.md → «Финал ветки»). GameTest — через `scripts/test.sh gametest` (замок «один сервер на машину»).
  Машина общая с другими исполнителями. Красный прогон не коммитится.
- Коммитишь сам, по docs/GIT.md, частями по мере готовности.
- Отчёт в конце: хэши коммитов, итог тестов (сколько прошло, сколько упало), что не сделано и почему.
  «Похоже, работает» — не отчёт.

## Язык

- **Пользователю отвечать ТОЛЬКО на русском языке. Без исключений.** Идентификаторы, команды и имена
  пакетов — в оригинале, но весь текст ответа в чат — русский.
- Документация, сообщения коммитов, тексты assertion и логов — на русском. Код (имена) — на английском.

## Решения пользователя

- **Версии Minecraft, NeoForge, Gradle-плагинов и зависимостей выбирает пользователь.** Агент собирает
  данные (что есть, что стабильно, сколько модов поддерживает) и приносит варианты с ценой каждого,
  но сам версию не меняет и не выбирает.
- Сейчас: Minecraft 1.21.1, NeoForge 21.1.257, Java 21 — выбор пользователя от 2026-10-10.
- Лимиты плана (2026-10-11): `repeat.times` ≤ 64, `wait.ticks` ≤ 6000 (5 мин), `follow.radius` ≤ 16,
  тайм-аут `goto` ≈ 40 тиков на блок. Менять — только с согласия пользователя.
- Дух держит чанки вокруг себя загруженными и тикающими, как игрок (2026-10-11): радиус по умолчанию —
  simulation distance сервера. Поэтому дальность `goto` ограничена только границами мира.
- Стратег духов — внешний ИИ-агент, который ходит в мод по REST в локальной сети; мод сам LLM не вызывает
  (2026-10-11). Сначала агент на opencode (бесплатные модели), затем реальный агент на Sonnet 5.5.
- REST-мост живёт внутри мода: HTTP-сервер поднимается при старте сервера, порт — из серверного конфига мода;
  слушает LAN, **без авторизации** — сеть доверенная (2026-10-11).
- Решения главного агента по поручению пользователя (2026-10-11): один Gradle-модуль с пакетами (изоляцию
  `core` держит сторож); наблюдение для ИИ — сводка + точечные запросы (scan с фильтром, locate);
  MCP — позже, адаптером поверх REST.

## Когда спрашивать

- **Публикация мода и перезапуск сервера — ТОЛЬКО по предварительному согласованию с пользователем.**
  Самовольно deploy/restart не выполнять и `scripts/publish.sh` без подтверждения не запускать.
- Решай сам, если правильное поведение очевидно из здравого смысла игрока или из кода.
- Спрашивай, только когда ответ меняет работу и вывести его неоткуда: число из геймдизайна, изменение,
  которое трогает существующий мир игроков, два прочтения слов пользователя, дающие разную работу.
  Неси варианты и цену каждого, а не «уточните, пожалуйста».
- Даже спрашивая, не останавливайся целиком: сделай всё, что от ответа не зависит, и предъяви вопрос
  вместе с готовым куском.

## Отчёт в чат

- Коротко: абзац на результат, строка на факт. Что сделано и работает, число, которое можно проверить,
  дефект, о котором пользователь не знал, последствие для мира, вопрос, без которого работа встанет.
- Не идут в чат: ход отладки, пересказ планов, промежуточные «первый шаг готов».
- «Похоже, работает» — не результат. Результат подтверждается командой (вывод тестов, сборки)
  и хэшем коммита.

## Дисциплина вывода

- Фильтруй вывод у источника: `grep` по логу сборки и сервера вместо печати целиком.
- Не опрашивай фоновую задачу ради прогресса — она сама сообщит о завершении.
- Не ищи от корня файловой системы: ищи в репозитории, исходники Minecraft/NeoForge — в кэше Gradle
  (`~/.gradle/caches`) или через сгенерированный IDE-проект.
- Читай код целево: нужный класс и диапазон строк, а не весь файл.

## Общие инструкции и частные случаи

- Общие правила (этот файл, `docs/*.md`, README) не пополняются историями отдельных багов, частными
  командами диагностики и путями к их результатам. Частное поведение фиксируется тестом, разбор —
  в материалах задачи или чате.
- Урок не удаляют — его уточняют. Если правило кажется лишним, оно непонятно написано.
- Новое правило «будь внимательнее» не пишется: вместо него нужен тест или сторож, который ловит ошибку.

## Сервер

Сервер и его git — соседний каталог `/opt/minecraft/server` со своим README. Собранный мод ставится туда
скриптом `scripts/publish.sh`, но только по предварительному согласованию с пользователем (см. `docs/PUBLISH.md`).
Мир и конфиги сервера коммитятся только его скриптом `scripts/snapshot.sh`.
