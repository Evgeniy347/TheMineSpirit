# Веса графа на видеокарте — отчёт

## Что сделано

| Файл | Назначение |
|---|---|
| `graph_model.py` | Перенос правил Java (`GraphPlanner`, `GraphFlow`, `SupplyGraph`, `GraphState`) один в один |
| `test_conformance.py` | Сверка с `conformance.json` (200 состояний) |
| `sim_gpu.py` | Пакетная симуляция миров на torch/CUDA: этапы 1–3, духи берут разные задания |
| `search.py` | Эволюционный поиск 489 множителей весов в пределах ±50 % |
| `best-weights.json` | Найденные множители и готовые абсолютные значения (в `graph.json` не внесены) |

## Сверка с Java

`python test_conformance.py` — **200/200**: набор заданий, `feasible` и `chance` совпадают точно,
`priority` расходится не больше чем на 1.

Симуляция сверена с заново выгруженным Java-путём (`GraphSimulationTests.simulate_Baselines_WriteTrailReport`,
в `mutationTest` не входит). Шаги Python и Java совпали точно:

| Старт | Python | Java |
|---|---|---|
| база 0 (пусто) | 116 | 116 |
| база 1 (обжитый) | 64 | 64 |
| база 2 (тесно) | 53 | 53 |
| база 3 (этап 2) | 1556 | 1556 |
| база 4 (10 духов) | 87 | 87 |

Число «1395» из старой заметки устарело: сейчас в графе есть необязательные постройки этапа 1
(`campfire`, сады), они стоят `ABSENT` и входят в `unbuilt`, поэтому этап 1 не повышается.
Это поведение самого Java; Python повторяет его, а не «чинит».

## Поиск

Параметры — 489 множителей в диапазоне 0.5…1.5: база каждого предмета (172), база каждой постройки (58),
вес каждого пути (256), `decay`, `urgentBoost`, `buildReadyBoost`.

Эволюция: популяция 16, 10 поколений, сид 1, элитная средняя, пакет миров на CUDA. Каждое поколение
проверяет кандидатов на двух стартах: обязательный `stage2-full` (настоящая база 3 из `GraphMutations`)
и один из стартов поздней игры по кругу. Так отбрасываются векторы, которые ломают прохождение настоящей базы.
Матрица `(I − A)·p = r` решается на видеокарте одним `torch.linalg.solve`.

| Старт | До | После | Выигрыш |
|---|---|---|---|
| `stage2-full` (Java база 3) | 1556 | 1349 | −13.3 % |
| `late3-half` | 702 | 652 | −7.1 % |
| `late3` | 954 | 837 | −12.3 % |
| `stage2-all` | 1246 | 1070 | −14.1 % |
| **Сумма** | **4458** | **3908** | **−12.3 %** |

Все четыре старта доходят до конца этапа 3 (этап 4).

Ключевые найденные значения:

| Параметр | Было | Стало |
|---|---|---|
| `decay` | 0.5 | 0.75 (упёрлось в +50 %) |
| `urgentBoost` | 20 | 17 |
| `buildReadyBoost` | 60 | 76 |

Остальные 486 множителей — в `best-weights.json` (секции `parameters`, `weights` и `absolute`).
В `graph.json` ничего не внесено.

## Что не вышло и чего ждёт

- Базы 0–2 структурно застревают на этапе 1 независимо от весов: необязательные постройки `ABSENT`
  не дают повысить этап, а `requireBuilding` для `ABSENT` только пишет просьбу. Весами это не лечится.
- `./gradlew mutationTest` не запускался — по правилам нужно согласие владельца. Найденные веса проверены
  только Python-моделью, совпадающей с Java на 200 контрольных случаях и на базовых прогонах.
- Поиск сделан одним сидом на полном векторе; больше сидов/поколений может дать ещё выигрыш, но каждый
  прогон занимает ~20 минут на GTX 1060.

## Запуск

```bash
./gradlew graphExport
cd tools/graph-gpu
python test_conformance.py
python sim_gpu.py
python search.py --mode sensitivity
python search.py --mode es --generations 10 --population 16 --seeds 1
```
