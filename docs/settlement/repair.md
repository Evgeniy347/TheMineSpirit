# Реестр построек, ремонт, выбор следующей стройки, пересмотр плана

## Реестр построек

Каждая законченная постройка и каждый сегмент ограждения — запись реестра поселения (в мире, рядом с доской):
`id`, семья, уровень, файл схемы, начало и поворот, слот плана, состояние
(`BUILDING` / `BUILT` / `DAMAGED` / `UPGRADING` / `RELOCATING`), тик постройки, тик последней проверки.
Из реестра получаются факты доски (`SettlementFacts`: есть забор, дома, склад…) вместо нынешнего «всё у дома»,
и `done` уровня в `GET /v1/board`. Индекс «клетка → постройка» — по участкам (прямоугольники), без карты блоков.

## Проверка (обход)

- **Плановая**: по кругу, бюджет клеток на тик из данных (ориентир 256 клеток/тик), каждая постройка — не реже
  раза в игровой день. Сравнение мира со схемой текущего уровня — той же площадкой, что у стройки
  (`SchematicSite`: какие клетки не совпадают).
- **Событийная**: взрыв, пожар, сломанная мобом дверь, украденный эндерменом блок внутри участка — постройка
  проверяется в ближайший тик вне очереди.
- **Что не считается повреждением** (данные `repair.json`): свойства-состояния (дверь, калитка, люк открыты;
  кровать занята; костёр погас; уровень воды в котле), содержимое сундуков и бочек, «мягкие» клетки схемы
  (цветы, посевы, саженцы и выросшие из них деревья, ковры под снегом), снег-слой, лианы, трава на земле двора.

## Что чинится и как

| Расхождение | Действие |
|---|---|
| ожидался блок, стоит воздух / вода / огонь / песок-гравий-земля | поставить по схеме (природное убрать) |
| ожидался воздух, лежит природное (осыпь, снег-блок, земля после взрыва) | убрать |
| стоит блок, поставленный игроком | вернуть к схеме: сообщение в чат, 3 минуты на уборку с напоминанием раз в минуту, затем убрать (решение 15) |
| стоит чужой мобовый/природный «мусор» (паутина, тыква-голова не по схеме) | убрать |
| повреждено > 50 % блоков постройки | не ремонт, а задание «отстроить уровень заново» с полным расчётом материалов |

- Задание доски `REPAIR_BUILDING` (есть) несёт схему, начало и поворот записи реестра; материалы — по нехватке
  (гейт доски ставит «нарубить/добыть», как у стройки). `REPAIR_FENCE` (есть) — для сегментов ограждения.
- Завершённый ремонт при сохранившейся недостаче переоформляется: иначе постройка ниже порога перестройки
  (например, хижина 92%, 8% недостачи) остаётся повреждённой навсегда.
- Приоритеты (данные `board.json`, покрыты тестами): дыра в стене и воротах — 95 (как оборона), жильё — 70,
  ремесло и склады — 60, декор двора и улицы — 30. Пробоина в стене ночью или при враге рядом — один дух строит,
  остальные прикрывают (чеклист 34, координатор).
- Воронки за территорией — уже `FILL_CRATER`; внутри участка яма от взрыва — часть ремонта постройки.

## Выбор следующей стройки (тактика)

Правила нужды — данные `settlement_demand.json`, каждое число покрыто тестом (правило проекта о приоритетах):

| Нужда | Условие | Задание |
|---|---|---|
| спальные места | кроватей < духов + 1 (игрок) | следующий уровень дома с местом или новый дом в свободном слоте `h` |
| склад | свободно < 20 % (todo) | следующий уровень `storage`, затем второй склад |
| рабочее место | у профессии нет станка в радиусе (todo «профессия привязана к рабочей точке») | постройка профессии уровня 1 |
| этап | до следующего этапа не хватает построек из `stages.json` | недостающая, по порядку таблицы этапа |
| ограждение | уровень стены < уровня этапа | улучшение сегментов от ворот |
| свет | на территории есть клетки со светом 0 | `LIGHTING` по участку |
| красота | всё выше выполнено, дух свободен | следующий уровень любой постройки или улиц (низкий приоритет) |

Тактика не строит цепочек: выбирает одно задание по правилу, остальное делает гейт доски (todo 17.10).

## Улучшение на месте

1. Материалы следующего уровня считаются по разнице схем (что добавить и что убрать), а не по полной схеме.
2. Перед стройкой — снятые блоки уходят в инвентарь/на склад (кроме природных), сундуки уровня N стоят на своих
   местах и в уровне N+1 (сторож, format.md) — содержимое не переносится.
3. Стройка — обычная по схеме уровня N+1 с тем же якорем (дверью); на время — состояние `UPGRADING`, жильё
   остаётся жильём (кровати ставятся до сноса старых).

## Пересмотр плана (раз в игровой день)

- Проверка: слоты не задеты новыми постройками игрока и водой; реестр совпадает с миром; нужды → новые слоты;
  этап → улучшения и линия стены.
- Итог в чат одной строкой: «план в порядке» или «план пересмотрен: <что>, задания на доске» (todo 14.10).
- Перенос — существующее задание `RELOCATE_BUILDING`; неподвижны вход в шахту и сегменты стены у ворот.
- Расширение границы (если выбран рост кольцами) — задания «поставить новый сегмент» по внешней линии, затем
  «разобрать старый» — именно в таком порядке, чтобы ограждение не исчезало.
