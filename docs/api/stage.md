### GET /v1/settlement/stage

Текущий этап поселения и почему он такой. Этап считается по журналу доски (`SettlementStage.of`): он стоит на
первом этапе, у которого не закрыта хотя бы одна постройка. Ответ:

```json
{ "stage": 2, "stages": 4,
  "missing": {"BUILD_MINE": 2},
  "requirements": [
    {"stage": 1, "id": "BUILD_HOUSE", "level": 1, "closed": true, "world": "ready"},
    {"stage": 1, "id": "BUILD_MINE", "level": 1, "closed": true, "world": "not_ready"},
    {"stage": 2, "id": "BUILD_MINE", "level": 2, "closed": false, "world": "unknown"}
  ] }
```

- `stage` — этап, на котором стоит поселение; `stages + 1` значит «все этапы закрыты»;
- `missing` — остаток текущего этапа по журналу (чего не хватает до закрытия);
- `requirements` — постройки всех этапов до текущего включительно: что закрыто журналом (`closed`) и что стоит
  по миру (`world`: `ready`, `not_ready`, `unknown`). Расхождение `closed: true` и `world: not_ready` — это
  и есть «этап открылся, а постройка не готова»: лечится откатом этапа ниже.

### POST /v1/settlement/stage

Откат этапа (и `PUT` — то же самое). Мир не ломается: постройки не сносятся, с доски снимаются задания более
высоких этапов, снимаются отметки журнала, а постройки целевого этапа, не готовые по миру, снова открываются на
ремонт обычным расписанием духа. Тело:

```json
{ "request_id": "3f1c2d3e-0000-4000-8000-000000000000", "stage": 1,
  "by": "owner", "reason": "шахта 96%, двор 91% — этап не закрыт целиком" }
```

- `request_id` — обязателен, UUID; повтор с тем же телом возвращает прежний ответ, с другим — 409 `conflict`;
- `stage` — обязателен, целевой этап (с первого); вперёд этап не ставится — он закрывается постройкой;
- `by` — кто откатил, по умолчанию `rest`; попадает в карточку `[stage] откат 2→1: причина …, кем …`;
- `reason` — причина, по умолчанию `откат этапа`;
- лишнее поле — 400 `invalid_request` с именем поля.

Ответ `200`:

```json
{ "previous": 2, "stage": 1, "changed": true,
  "forgotten": ["building:BUILD_MINE:1", "building:BUILD_WAREHOUSE:2"],
  "cancelled": ["graph:building:plaza"], "request_id": "3f1c2d3e-…" }
```

- `forgotten` — снятые отметки журнала (по ним этап возвращается назад);
- `cancelled` — задания более высоких этапов, снятые с доски;
- повторный откат на текущий этап — успех с `changed: false`, доска не меняется.

Отказ `409 conflict`: этап вперёд, целевой этап закрыт по миру целиком (откатывать нечего) или этап вне
списка. Отказ не трогает ни одной отметки и ни одного задания.

Откат переживает перезапуск: снятие отметок пишется в журнал досок (`REOPENED`), а состояние доски сохраняется
в данных мира. Выполняется на серверном потоке, как и остальные изменения мира.

#### Откат для владельца

```bash
curl -s -X POST http://127.0.0.1:8765/v1/settlement/stage \
  -H 'Content-Type: application/json' \
  -d "{\"request_id\":\"$(uuidgen)\",\"stage\":1,\"by\":\"owner\",\"reason\":\"шахта 96%, двор 91%\"}"
```

Сначала посмотреть, что происходит: `curl -s http://127.0.0.1:8765/v1/settlement/stage`.
