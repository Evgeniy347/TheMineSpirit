# Уровень поселения

Уровень выбирается только через REST: автоматический обмер больше не меняет высоту. `level` — уровень ног
(`anchor.y`), верх грунта `y0 = level − 1`. Проходы, улицы и забор стоят на `level`.

## `GET /v1/settlement/level`

```json
{"level": 68, "y0": 67, "anchor": {"x": 0, "z": 0}, "rule": "SettlementLevel.v1"}
```

Пока уровень не задан — 404 `not_found`.

## `POST /v1/settlement/level/preview`

Сухой расчёт, мир не меняется. Если плана ещё нет, он размечается; уровень не меняется.

```json
{
  "level": 68, "y0": 67, "anchor": {"x": 0, "z": 0},
  "cut": 2037, "fill": 587, "surplusPercent": 25,
  "stock": {"blocks": 5120, "covered": true},
  "water": {"blocks": 34, "median": 62, "floor": 63},
  "area": {"columns": 812, "min": 60, "max": 75}
}
```

- `cut`/`fill` — срезка и подсыпка рельефа на площади финального этапа; `fill` до 10 блоков на колонку.
- `stock.blocks` — земля и земля с травой со склада (сундуки и духи). Она оплачивает подсыпку: высота
  опускается, только если `cut + stock` не покрывает `fill` с запасом `surplusPercent`.
- `water` — поиск от базовой точки плана на 128 блоков в каждую сторону. Берётся медиана уровней воды;
  если колонок воды меньше 10, ограничения нет (`median`/`floor` = null). Минимальные ноги —
  `median + 1`, чтобы верх грунта не оказался под водой.

## `PUT /v1/settlement/level`

```json
{"request_id": "3f1c2d3e-0000-4000-8000-000000000000", "level": 68, "by": "strategist", "reason": "выравнивание"}
```

- `request_id` обязателен: повтор с тем же id возвращает прежний ответ, другое тело — 409 `conflict`.
- `level` ниже воды (`median + 1`) или вне мира — 422 `invalid_plan`.
- Уровень выше воды разрешён. После записи план получает ту же высоту, событие пишется в журнал доски
  (`plot`, причина, кто и зачем).
- Других способов сменить уровень нет: сторож `SettlementLevelGuardTests` не даёт менять его мимо REST.
