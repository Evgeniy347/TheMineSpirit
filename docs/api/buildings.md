### Файл постройки (текстовый формат слоёв)

Каждая постройка — один файл `schematics/<id>.txt`; пресеты перечислены в `schematics/presets.json` (только id).
Проверка вне игры: `scripts/schematic.sh check` (разбор и сторожа), `scripts/schematic.sh show <id> [поворот]`
(материалы и срезы по слоям).

```
name: "Дом семьи на 3"      # пресету обязательны name, type, stage, entrance
type: housing
stage: 1
level: 1                    # необязательно: ступень постройки; requires: id предыдущей ступени
size: 9x8x9                 # Ш × В × Д
entrance: front             # вход: front (дверь/калитка в ближайшей к фронту строке) или x,y,z
exemptions:                 # исключения сторожей — только с причиной
  - rule: window
    reason: "склад без окон по замыслу"
legend:
  '#': oak_planks
  'D': oak_door[facing=south,hinge=left]
  'B': white_bed[facing=south]
  '1': oak_sign "руда"
layers:
  - y0 пол: |
      #########
```

Слои снизу вверх, отступ строк — на 4 больше отступа дефиса; первая строка слоя — фронт (z=0), символы слева
направо — +X. `.` — клетка обязана быть воздухом, пробел — не трогать. Дверь пишется одним символом в двух
слоях, кровать — в двух соседних клетках вдоль `facing` (изголовье по `facing`). Ошибка называет файл, строку и
что исправить. Пол выше земли — перед порогом крыльцо: строка за стеной со ступенькой (`*_stairs` к двери или
полублок) в y0 и `.` над ней; стены, крышу и высоту сторожа меряют по телу (слой порога), без крыльца. Пара
сундуков — `chest[facing=…,type=left|right]`. Правила качества — `SchematicRules` (свет, высота 3 под крышей,
ступенька, пары сундуков — для всех типов).
- `build_fence` (`block`, `gate`, `points`) — огородить замкнутый контур: `points` — углы
  в формате `"x,y,z"` (прямоугольник задаётся четырьмя углами), `block` — блок забора, `gate` —
  необязательный блок калитки (по умолчанию пусто — проход без двери). Калитка ставится в середине
  самого длинного ребра, её клетка из забора исключается. Забор стоит на одном уровне, диагональные рёбра
  отвергаются до первого блока; блоки берутся из инвентаря.
- `build_shelter` (`side`, по умолчанию 4) — поднять вокруг духа укрытие `3`×`3` или `4`×`4`: стены
  в два блока и крыша из первого полного блока инвентаря (тот же план, что у быстрого укрепления Fortify).
  Клетки духа остаются свободными; нет полного блока — `FAILED` с причиной. Итог — счётчики стройки
  (placed, skipped, have, missing, block), как у `fill`.
- `build_farm` (`crop`, `x1`, `z1`, `x2`, `z2`) — разбить грядку прямоугольником на уровне земли под
  ногами духа: вспахать клетки, у которых вода в четырёх блоках по горизонтали, посадить `crop`
  (культуры открытого грунта; какао и другие культуры на опоре отвергаются — для них `plant_crop`).
  Порядок — существующий планировщик фермы: мотыга, затем семена из инвентаря. Итог —
  tilled, planted, crop, cells; нехватка воды и места попадает в причину провала.
- `light_area` (`x`, `y`, `z`, `radius`, по умолчанию 16) — осветить факелами территорию вокруг точки:
  по карте блочного света квадрата `2*radius+1` выбирает минимум клеток факелов так, чтобы на земле не осталось
  клеток со светом ниже порога спавна враждебных мобов (в 1.21 — блочный свет 0). Факелы ставятся жадно из
  сетки-кандидата, на чужие постройки, в воду и на листья не ставятся, свои блоки дух помечает. Задача всегда
  завершается успехом с итогом: поле `missing` называет, скольких факелов не хватило, а пропущенные клетки
  (недостижимо, занято, защищено) попадают в счётчик пропусков. Повторный запуск доставляет недостающие.

Итог стройки (`result` успешной задачи) — объект со счётчиками:

```json
{ "placed": 8, "removed": 0, "skipped": 0, "failed": 0, "have": 8, "missing": 0, "block": "cobblestone" }
```

`block` — вид блока (у `clear_area`/`dig_area` с разными видами — пустая строка). У проваленной задачи
`result` пуст (`null`), числа — в `error`. Прогресс `done`/`target` есть у всех пяти (блоки обработано/всего).

Итог `dig_descent` — свой объект:

```json
{ "reached": true, "y": -58, "depth": 122, "blocks_dug": 366, "reason": "" }
```

reached — дошёл ли спуск до целевого этажа, y — достигнутый этаж, depth — сколько этажей пройдено,
blocks_dug — сколько блоков выкопано, reason — пуст или называет причину остановки (опасность,
нехватка факелов, недостижимая ступень). Прогресс `done`/`target` — шаги спуска.

Остальные скрипты каталога (по одному в строке; параметры — из описания скрипта, поведение — в реализации):

- `chop_target` (`x`, `y`, `z`, `replant`) — срубить конкретное дерево по координате ствола: разбор дерева,
  сбор дропа и посадка саженца как у `chop_tree` (без поиска по виду). Нет ствола по координате или дерево
  защищено политикой — `FAILED` с причиной
- `locate_block` (`filter`, `radius`) — найти ближайший блок по фильтру
- `locate_tree` (`species`, `radius`) — найти ближайшее дерево заданной породы
- `locate_container` (`radius`) — найти ближайший контейнер
- `follow` (`target`, `radius`) — следовать за целью на расстоянии
- `escort` (`target`, `radius`, `until`) — сопровождать и охранять игрока или духа: держаться в радиусе,
  защищать цель тактикой обороны и ждать рядом, пока задачу не отменят (`until` = 0) или не истечёт срок
- `explore` (`radius`, `budget`) — обойти область по детерминированной спирали (`budget` точек), запомнить
  руды, деревья, воду, лаву и мобов в память духа и вернуться к точке старта; за границу поселения — только
  группой или с игроком, ночью — нельзя
- `swim` (`x`, `y`, `z`) — плыть к цели, не тонуть: при нехватке воздуха дух выныривает к поверхности и
  продолжает путь. Итог — прибытие к точке
- `cross_water` (`x`, `y`, `z`) — переправа через воду между духом и целью только вплавь (упрощение
  владельца 18.10: мост в переправе не строится, блоки не тратятся). Воды по линии нет — идёт как `goto`
- `bridge` (`x`, `y`, `z`, `length`, `block`) — поставить мост длиной `length` блоков (1..64) от первой
  клетки без твёрдой опоры по направлению к цели и перейти его. Блоки — из инвентаря (земля, булыжник,
  гравий, песок, доски); нехватка — `FAILED` с числами, `block` необязателен. Лава в клетке или под ней —
  `FAILED` до постройки. Поставленные блоки дух помечает и не разбирает
- `flee` — убежать от угрозы
- `collect_drops` (`radius`, `filter`, `overflow`) — подобрать выпавшие предметы вокруг духа.
  `overflow`: fail — отказ при полном инвентаре, by_value — взять ценное, выбросив дешёвое,
  return_to_base — сдать лишнее на склад и продолжить. По умолчанию by_value
- `harvest_crop` (`crop`, `radius`, `replant`) — собрать урожай
- `plant_crop` (`crop`, `radius`, `count`) — посадить культуру
- `till` (`radius`, `count`) — вспахать землю под грядку
- `bone_meal` (`crop`, `radius`, `count`) — подкормить посевы костной мукой
- `breed` (`species`, `radius`, `pairs`) — свести пару животных
- `feed` (`species`, `radius`, `count`, `babiesFirst`) — покормить стадо
- `shear` (`radius`, `count`) — постричь овец
- `milk` (`radius`, `count`) — подоить коров
- `collect_eggs` (`radius`) — собрать яйца в загоне
- `harvest_hive` (`radius`, `count`) — собрать соты ножницами или мёд стеклянной бутылкой с улья/гнезда
  уровня мёда 5. Перед сбором — костёр в 1–5 блоках ниже улья: есть дым — пчёлы не злятся. Костра нет —
  дух ставит его из материалов (3 палки, 3 бревна, 1 уголь); нет материалов — `FAILED`, улей не тронут.
  Ножницы дают 3 соты, бутылка — бутылку мёда; пчёл не убивают
- `cull` (`species`, `keep`, `radius`) — забить лишних голов
- `herd_check` (`species`, `radius`) — сосчитать стадо
- `hunt` (`species`, `radius`, `count`) — забить диких животных
- `capture` (`species`, `radius`) — привести животное вида приманкой (корм вида в инвентаре) в загон у дома
  духа (радиус 3 от дома); блоков не ставит. Нет корма, дома или животного вне загона — `FAILED` с причиной
- `fish` (`count`, `duration_ticks`, `radius`) — ловить рыбу удочкой у открытой воды
- `bucket_fish` (`count`, `radius`) — поймать рыбу ведром у открытой воды (не больше предела из `fishing.json`)
- `craft` (`item`, `count`, `radius`) — скрафтить предмет
- `smelt` (`item`, `count`, `radius`) — переплавить предмет
- `equip` (`item`) — надеть предмет
- `acquire` (`item`, `count`) — добыть предмет любым способом
- `attack` (`target`) — атаковать цель
- `defend` (`target`) — защитить цель
- `retreat` — отступить
- `disengage` (`target`, `distance`) — выйти из боя: отойти на `distance` (1..16, по умолчанию 5) от врага
  `target` (по умолчанию — враждебные мобы) и прекратить бой, не убегая далеко (в отличие от `flee` и `retreat`)
- `fill_crater` (`crater`) — засыпать воронку от взрыва ровно до уровня земли
- `deliver` (`item`, `count`, `to`) — доставить предмет адресату
- `give` (`item`, `count`, `to`) — передать предмет игроку или духу (то же поведение, что у `deliver`)
- `drop_to_player` (`item`, `count`, `to`) — подойти к адресату и бросить предмет ему под ноги (предмет
  остаётся на земле с задержкой подбора, в инвентарь не кладётся)
- `take` (`item`, `count`, `from`) — подойти к игроку или духу и забрать предмет в свой инвентарь;
  нехватка у источника или места у духа — `FAILED` с числами, предметы не двигаются
- `report` (`to`) — доложить в чат: задача и её статус, здоровье, сытость, краткий инвентарь, координаты и мир;
  без `to` — всем игрокам в радиусе слышимости, с `to` (`player:<имя>`) — только ему
- `swap_tool` (`block`) — сменить предмет в руке на лучший целый инструмент для блока из инвентаря;
  подходящего нет — `FAILED` с причиной
- `drink_potion` (`type`) — выпить зелье из инвентаря по типу (healing, regeneration, fire_resistance
  и т. п.); совпадает имя зелья или эффекта, эффекты применяются, зелье убирается
- `meet` (`target`) — встретиться с целью
- `say` (`text`) — произнести сообщение
- `wait` (`ticks`) — ждать заданное число тиков
- `sleep` — лечь спать в кровать ночью: дух идёт к своей или ближайшей свободной кровати в поселении, ложится
  (ванильная механика сна) и просыпается утром или при угрозе/уроне; без свободной кровати — `FAILED` с причиной
- `close_door` (`x`, `y`, `z`) — подойти к двери и закрыть её
- `use_block` (`x`, `y`, `z`) — подойти к блоку и нажать его, как правой кнопкой: рычаг и кнопка
  переключаются, дверь открывается или закрывается. Чужой механизм в постройке игрока вне разрешённой
  области не трогается, отказ называет политику защиты (чёрный список защиты на нажатие не действует)
- `open` (`x`, `y`, `z`) — открыть дверь, люк или калитку (свойство OPEN); сундук открывается и сразу
  закрывается. Уже открытая дверь — успех
- `set_combat_mode` (`mode`) — сменить режим тактики духа: `passive`, `defensive`, `protect` или
  `aggressive` (guard_area включается зоной охраны, а не строкой режима). Смена режима попадает в журнал
  решений тактики
- `repair_tool` (`item`) — починить инструмент или броню. На наковальне материалом ремонта (железный — слитком,
  алмазный — алмазом, деревянный — досками, и так по типу) добавляет 25% максимальной прочности; двумя одинаковыми
  повреждёнными в точиле сливает их в один предмет с суммой прочности и бонусом 5% от максимума (зачарования
  теряются, поэтому зачарованное точилом не чинится). Способ выбирается дешевле по опыту и материалу, при этом
  зачарованный инструмент чинится только наковальней. Не чинит, пока прочность выше порога maxDurabilityPercent
  из data/theminespirit/repair/repair.json. Итог несёт предмет, способ, материал, прочность и максимум
