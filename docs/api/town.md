# Карта поселения: .drawio и правки через REST

Поселение задаётся **картой** — участками, улицами и отрезками стены. Наружу карта ходит только в
`.drawio`: его рисуют и правят в diagrams.net, а мод раскладывает фигуры в план поселения. JSON-контракта
карты больше нет: `GET /v1/town/plan`, `POST /v1/town/preview` и `POST /v1/town/apply` принимают и отдают
XML. Внутри мира карта хранится тем же `.drawio` без PNG-подложки, сжатым в NBT; старое сохранение с
JSON-картой переносится при чтении.

Координаты — блоки `x,z` без высоты; высоту задаёт уровень поселения (`PUT /v1/settlement/level`, см.
[level.md](level.md)). Размер участка закреплён за постройкой в `town.json` и одинаков для всех уровней.

## Объекты карты

| Объект | Атрибуты `tm*` | Правила |
|---|---|---|
| `meta` | `tmFormat`, `tmRevision`, `tmAnchorX`, `tmAnchorZ`, `tmX1`, `tmZ1`, `tmX2`, `tmZ2`, `tmScale` | скрытая ячейка выгрузки; без неё файл не принимается |
| участок | `tmKind="plot"`, `tmId`, `tmBuilding`, `tmFacing`, `tmX1`, `tmZ1`, `tmX2`, `tmZ2` | `tmId` уникален; `tmBuilding` — id из `town.json`; размер равен каталогу; `tmFacing` — `north/south/east/west` |
| улица | `tmKind="street"`, `tmId`, `tmKindValue="main" или "side"`, `tmX1`…`tmZ2` | координаты в блоках; ширина — `x2-x1+1` или `z2-z1+1` |
| стена | `tmKind="wall"`, `tmX1`…`tmZ2` | прямые отрезки; вместе образуют замкнутую линию |

Минимальная ширина улицы — **5** (главные обычно 7). Проход в стене — не объект, а **отрезок улицы**,
пересекающий линию стены: стена рвётся на ширину улицы, ворот и калиток-объектов нет. Кольцевых улиц нет.

## `GET /v1/town/plan` и `GET /v1/town/plan.drawio`

Оба адреса отдают один и тот же `.drawio`; `plan.drawio` дополнительно приходит как файл-вложение.

- `Content-Type: application/xml; charset=utf-8`.
- Внутри `<mxfile>` лежит PNG-подложка (base64), прямоугольники участков, линии улиц, прямоугольники стены
  и скрытая ячейка `meta`.
- Участки, улицы и стена — прямоугольники; у стены `rotation` задаёт наклон. Геометрия фигур — пиксели
  подложки: `(блок − tmX1 из meta) × tmScale`; мировые координаты продублированы в `tmX1…tmZ2` и по ним
  карта читается обратно только у фигур без геометрии. После перемещения или растягивания фигуры в
  diagrams.net применяются **новые** координаты из `mxGeometry`, а не старые `tm*`.
- `?x1=…&z1=…&x2=…&z2=…&scale=…` задаёт рамку подложки; без неё берётся граница плана; `scale` — 1…8
  (по умолчанию 2). Лимиты: 160 000 клеток и 4096 пикселей по стороне.
- diagrams.net может сохранить диаграмму сжатой — мод распаковывает и такой файл.

## `GET /v1/town/terrain.png?x1=…&z1=…&x2=…&z2=…&scale=…`

PNG местности в стиле ванильной карты: цвета, вода и лава, сетка каждые 16 блоков и подписи координат
каждые 32. Координаты `x1,z1,x2,z2` обязательны; `scale` — 1…8 (по умолчанию 2). Лимиты те же, что у
подложки `.drawio`.

## `POST /v1/town/preview` и `POST /v1/town/preview.drawio`

Тело — `.drawio` из выгрузки (можно после правок). Ответ — PNG: местность плюс наложенный план. Каждый
участок закрашен цветом этапа, подписан `tmId`, сторона двери отмечена буквой `N/S/E/W`; улицы серые,
стена тёмная. Превью ничего не меняет в мире и не требует валидной карты — по нему удобно искать ошибки.

```bash
curl -sS -X POST 'http://127.0.0.1:8765/v1/town/preview.drawio' \
  -H 'Content-Type: application/xml' --data-binary @town-plan.drawio -o preview.png
```

## `POST /v1/town/apply` и `POST /v1/town/apply.drawio`

Применяет карту: разбирает `.drawio`, проверяет фигуры по миру и, если ошибок нет, запоминает карту и
перестраивает план поселения. Тело — XML, `request_id` передаётся в запросе:

```bash
curl -sS -X POST 'http://127.0.0.1:8765/v1/town/apply.drawio?request_id=plan-2026-11-25-1' \
  -H 'Content-Type: application/xml' --data-binary @town-plan.drawio
```

Ответ: `{"ok":true,"revision":8,"plots":36,"streets":12,"wall":4}`.

- `request_id` необязателен: без него ключом идемпотентности становится отпечаток тела. Повтор с тем же
  телом возвращает прежний ответ, другое тело с тем же `request_id` — 409 `conflict`.
- `tmRevision` из `meta` сверяется с ревизией мира: устаревшая даёт 409 `conflict` с `expected/received` —
  карту надо забрать заново, иначе правка затрёт чужую.
- `tmAnchorX/tmAnchorZ` обязаны совпадать с центром поселения (медианой домов), иначе 422 `invalid_plan`.
- Удалять скрытую `meta`, менять `tmFormat`, `tmScale` и координаты `tm*` вручную не нужно: двигайте
  фигуры в diagrams.net — мировые координаты пересчитываются из `meta`.

## Ошибки карты

Ошибки разбора и валидации — 422 `invalid_plan`; ответ называет причину, в `details.errors` перечислены
все находки: `{"object": "barn", "kind": "overlap", "message": "…"}`.

| Код | Когда |
|---|---|
| `duplicate` | повтор `tmId` участка или улицы |
| `building` | `tmBuilding` нет в `town.json` |
| `size` | размер участка не равен каталогу постройки |
| `facing` | сторона двери не `north/south/east/west` |
| `outside` | участок, улица или стена вышли за границу поселения |
| `water` | участок, улица или стена задели воду (огибать, а не засыпать) |
| `street` | участок стоит на улице |
| `overlap` | участки накладываются (названы оба `tmId`, указан зазор) |
| `kind` | вид улицы не `main/side` |
| `narrow` | улица уже 5 клеток |
| `segment` | отрезок стены не прямой и не под 45° |
| `loop` | стена не замкнута, у поста не два соседа или части не соединены |

## Старый план

У мира без карты мод один раз переносит сохранённый план в карту (`TownMapConvert`): участки получают
`tmId` постройки, улицы раскладываются в прямоугольники, линия ограды — в отрезки стены. Дальше источник
истины — только карта; автоматической раскладки нет, правка идёт заменой фигур в `.drawio`.
