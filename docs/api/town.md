# Карта поселения: 2D-разметка и правки через REST

Плана-планировщика больше нет: поселение целиком задаётся **картой** — списком участков, улиц и отрезков
стены. Карта хранится в мире (сжатый JSON) и правится только REST: стратег забирает JSON, меняет объекты
и отправляет обратно. Мод раскладывает карту в план поселения (`TownMapRules`), а PNG-превью показывает
ровно то, что получится в мире.

Координаты — блоки `x,z` без высоты; высоту участка задаёт отдельный уровень поселения
(`PUT /v1/settlement/level`, см. [level.md](level.md)). Размер участка закреплён за постройкой в `town.json`
и одинаков для всех уровней.

## Объекты карты

| Объект | Поля | Правила |
|---|---|---|
| `anchor` | `x`, `z` | центр поселения (медиана домов духов): координаты карты считаются от него |
| `plots[]` | `id`, `building`, `x1`, `z1`, `x2`, `z2`, `facing` | `id` уникален; `building` — id постройки из `town.json`; размер равен каталогу; `facing` — `north/south/east/west` (сторона двери) |
| `streets[]` | `id`, `kind`, `x1`, `z1`, `x2`, `z2` | `kind`: `main`, `side`, `ring`; у `ring` координат нет — кольцо считается от границы |
| `wall[]` | `x1`, `z1`, `x2`, `z2` | только прямые отрезки (по одной оси); вместе образуют замкнутую линию |

Минимальная ширина улицы — **5** (главные обычно 7). Ширина задаётся прямоугольником: `x2-x1+1` или
`z2-z1+1`. Проход в стене — не объект, а **отрезок улицы**, пересекающий линию стены: стена рвётся на
ширину улицы, ворот и калиток-объектов нет.

## `GET /v1/town/plan`

Возвращает текущую карту в том же формате, который принимает `/v1/town/apply`:

```json
{
  "revision": 7,
  "anchor": {"x": 0, "z": 0},
  "bounds": {"x1": -144, "z1": -144, "x2": 144, "z2": 144},
  "plots": [
    {"id": "hut", "building": "hut", "x1": -10, "z1": 8, "x2": 5, "z2": 23, "facing": "south"}
  ],
  "streets": [
    {"id": "main_x", "kind": "main", "x1": -144, "z1": -3, "x2": 144, "z2": 3},
    {"id": "ring", "kind": "ring"}
  ],
  "wall": [
    {"x1": -144, "z1": -144, "x2": 144, "z2": -144}
  ]
}
```

`bounds` — граница участка поселения (справочно: участок обязан лежать внутри неё). `revision` растёт при
каждом применении; в теле `/v1/town/apply` его можно передать обратно — устаревшая ревизия даёт 409.

## `GET /v1/town/terrain.png?x1=…&z1=…&x2=…&z2=…&scale=…`

PNG местности в стиле ванильной карты: цвета ванильной карты, вода и лава отдельными цветами, сетка каждые
16 блоков и подписи координат каждые 32. Координаты `x1,z1,x2,z2` обязательны; `scale` — 1…8 (по умолчанию 2).
Лимиты: рамка до 160 000 клеток, сторона картинки до 4096 пикселей — иначе 400.

## `GET /v1/town/plan.drawio?x1=…&z1=…&x2=…&z2=…&scale=…`

Карта для ручной правки в diagrams.net: XML `.drawio` с PNG-подложкой внутри (base64). Участки — прямоугольники,
улицы и отрезки стены — отдельные линии; у фигур атрибуты `tmKind`/`tmId`, скрытая ячейка `meta` хранит
ревизию, якорь, рамку и масштаб для обратной загрузки. Координаты фигур — пиксели подложки:
`(блок − x1) × scale`. Без `x1,z1,x2,z2` берётся граница плана; `scale` — 1…8 (по умолчанию 2).
Проёмы ворот — не фигуры: их даёт пересечение улицы со стеной. Кольцевая улица — подпись `кольцо: …`:
у неё нет координат, кольцо считается от границы.

## `POST /v1/town/preview`

Тело — карта в формате `/v1/town/plan` (без `request_id`). Ответ — PNG: местность плюс наложенный план,
как карта по кнопке J игрока. Каждый участок закрашен цветом этапа, подписан `id` постройки, сторона двери
отмечена буквой `N/S/E/W`; улицы серые, стена тёмная (проёмы улиц не закрашиваются), сетка координат поверх.
Превью ничего не меняет в мире и не требует валидной карты — наоборот, по нему удобно искать ошибки.

## `POST /v1/town/apply`

Применяет карту: валидирует её и, если ошибок нет, запоминает в мире и перестраивает план поселения.

```json
{
  "request_id": "plan-2026-11-24-1",
  "revision": 7,
  "anchor": {"x": 0, "z": 0},
  "plots": [
    {"id": "hut", "building": "hut", "x1": -10, "z1": 8, "x2": 5, "z2": 23, "facing": "south"},
    {"id": "storage", "building": "storage", "x1": -32, "z1": 8, "x2": -17, "z2": 23, "facing": "north"},
    {"id": "yard", "building": "yard", "x1": 8, "z1": 8, "x2": 23, "z2": 23, "facing": "west"},
    {"id": "mine", "building": "mine", "x1": -10, "z1": 26, "x2": 5, "z2": 41, "facing": "south"},
    {"id": "orchard", "building": "orchard", "x1": 8, "z1": 26, "x2": 23, "z2": 41, "facing": "south"}
  ],
  "streets": [
    {"id": "main_x", "kind": "main", "x1": -144, "z1": -3, "x2": 144, "z2": 3},
    {"id": "side_1", "kind": "side", "x1": -98, "z1": 44, "x2": 98, "z2": 48},
    {"id": "ring", "kind": "ring"}
  ],
  "wall": [
    {"x1": -144, "z1": -144, "x2": 144, "z2": -144},
    {"x1": -144, "z1": -144, "x2": -144, "z2": 144},
    {"x1": -144, "z1": 144, "x2": 144, "z2": 144},
    {"x1": 144, "z1": -144, "x2": 144, "z2": 144}
  ]
}
```

Ответ: `{"ok":true,"revision":8,"plots":5,"streets":3,"wall":4}`.

- `request_id` обязателен: повтор с тем же телом возвращает прежний ответ, другое тело — 409 `conflict`.
- `revision` необязателен; если передан и не равен текущей, ответ 409 `conflict` с `expected/received` —
  карту надо забрать заново, иначе правка затрёт чужую.
- `anchor` обязан совпадать с центром поселения (медианой домов), иначе 422 `invalid_plan`.

## Ошибки карты

Ошибки валидации — 422 `invalid_plan`; ответ называет объект и причину, в `details.errors` перечислены все
находки: `{"object": "barn", "kind": "overlap", "message": "…"}`.

| Код | Когда |
|---|---|
| `duplicate` | повтор `id` участка или улицы |
| `building` | `building` нет в `town.json` |
| `size` | размер участка не равен каталогу постройки |
| `facing` | сторона двери не `north/south/east/west` |
| `outside` | участок, улица или стена вышли за границу поселения |
| `water` | участок, улица или стена задели воду (огибать, а не засыпать) |
| `street` | участок стоит на улице |
| `overlap` | участки накладываются (названы оба `id`, указан зазор) |
| `street_kind` | вид улицы не `main/side/ring`; кольцо задано дважды |
| `street_narrow` | улица уже 5 клеток |
| `wall_straight` | отрезок стены не прямой |
| `wall_loop` | стена не замкнута, у поста не два соседа или части не соединены |

## Старый план

У мира без карты мод один раз переносит сохранённый план в карту (`TownMapConvert`): участки получают `id`
постройки, улицы раскладываются в прямоугольники, линия ограды — в отрезки стены. Дальше источник истины —
только карта в мире; автоматической раскладки нет, `move_plot/add_plot/remove_plot/set_gates/add_path/
remove_path` удалены — правка идёт заменой объектов в JSON.
