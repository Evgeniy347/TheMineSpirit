# Карта поселения и точечные правки

Стратег читает карту целиком и правит её операциями. Размер участка закреплён за постройкой в
`town.json` и не меняется при подъёме уровня: дом 1-го и 4-го уровня стоят на одном участке.

## `GET /v1/town`

```json
{
  "anchor": {"x": 0, "y": 70, "z": 0},
  "region": {"minX": -144, "minZ": -144, "width": 289, "depth": 289, "area": 82944},
  "stage": 1,
  "plots": [{"id": "hut", "name": "Хижина", "stage": 1, "x": -20, "z": 12,
             "width": 16, "depth": 16, "facing": "south"}],
  "streets": [{"kind": "main", "minX": -3, "minZ": -144, "width": 7, "depth": 289}],
  "fence": {"posts": [[-144, -144]], "gates": [[-144, -80]]},
  "paths": [{"id": "path-1", "cells": [[-10, 0], [-9, 0]]}],
  "unplaced": []
}
```

## `POST /v1/town/edits`

```json
{"request_id": "…", "ops": [
  {"op": "move_plot", "id": "barn", "x": 40, "z": -40},
  {"op": "add_plot", "id": "library", "x": 60, "z": 20},
  {"op": "remove_plot", "id": "orchard_extra"},
  {"op": "set_gates", "gates": [[-144, -80], [0, -144]]},
  {"op": "add_path", "id": "path-1", "points": [[-10, 0], [-9, 0], [-8, 1]]},
  {"op": "remove_path", "id": "path-1"}
]}
```

- `request_id` обязателен: повтор с тем же id возвращает прежний ответ, другое тело — 409 `conflict`.
- Размер участка фиксирован: операция с другим размером отклоняется, `resize_plot` не поддерживается.
- Проверки: `id` из `town.json`, участок внутри региона, не на улице, не накладывается на другой;
  ворота только на постах линии ограды; тропинка внутри региона и не по участку.
- Ошибки валидации — 422 `invalid_plan` с русским текстом («участок 'barn' накладывается на 'storage'»);
  структурные ошибки тела — 400 `invalid_request`.

`POST /v1/town/validate` принимает то же тело и возвращает `{"ok": true, "dry_run": true}`, ничего не меняя.
