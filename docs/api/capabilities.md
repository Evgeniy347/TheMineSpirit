### GET /v1/capabilities

Каталог только реализованных скриптов (не весь набор из плана): ИИ не должен получить скрипт, который дух не выполнит.
Скрипты идут в порядке полного каталога; `params.required` перечисляет обязательные параметры.

```json
{ "scripts": [
  { "id": "chop_tree", "summary": "срубить деревья",
    "params": { "type": "object", "properties": {
      "species": { "type": "string", "default": "any",
        "enum": ["any", "oak", "spruce", "birch", "jungle", "acacia", "dark_oak", "mangrove", "cherry"] },
      "count": { "type": "integer", "minimum": 1, "maximum": 256, "default": 1 },
      "radius": { "type": "integer", "minimum": 1, "maximum": 32, "default": 16 },
      "replant": { "type": "boolean", "default": false } },
      "required": [] },
    "preconditions": ["есть подходящие блоки в радиусе сканирования"],
    "requires": [],
    "effects": ["брёвна срублены", "предметы подобраны в инвентарь"] } ] }
```

Поле requires — список структурных требований к шагу плана. Пример: kind = tool, tool = pickaxe, param = ore,
tiers = {"any": 1, "coal": 1, "iron": 2, …}, fallback = 1; значение параметра ore выбирает минимальный уровень
кирки из tiers, значение вне таблицы берёт fallback (0 — инструмент не требуется). Так mine_vein объявляет
уровни по руде, а gather — по блоку (камень — 1, железная руда — 2, обсидиан — 4; бревно в таблицу не входит).
Уровни: 1 — деревянная/золотая, 2 — каменная, 3 — железная, 4 — алмазная/незеритовая кирка.

Навигационные скрипты каталога: `goto_block` (подойти к ближайшему блоку вида; `block` обязателен),
`come_to_player` (подойти к игроку; без имени — к ближайшему), `patrol` (обход точек `points` списком
`"x,y,z"`, режим `loop`/`ping_pong`), `wander` (блуждание в радиусе до истечения `duration_ticks`),
`keep_distance` (держать дистанцию до цели), `escort` (сопровождать и охранять цель),
`explore` (обойти область по спирали и запомнить ресурсы и опасности), `walk_careful` (идти к точке,
не строя путь через обрыв), `step_over` (один шаг на соседнюю клетку), `climb` (влезть по лестнице, лиане
или строительным лесам вверх или вниз), `approach` (подойти к цели на стоянку в досягаемости ломки),
`swim` (плыть к цели, выныривая за воздухом), `cross_water` (переправа через воду вплавь),
`bridge` (мост через провал или воду из блоков инвентаря), `strip_log` (обтесать брёвна топором: `species`
порода обязательна, `count` 1–256, `radius` 1–100; без топора — `FAILED`).
Допуск прибытия — 1.25 блока, тайм-аут пути — 40 тиков на блок плюс 200 тиков запаса.

`brush` (`radius`, `count`) — почистить взрослого броненосца щёткой и подобрать щетину.

Стоимость движения (тики, предварительно — геймдизайн, меняются только с согласия владельца): шаг 5,
спринт 4, крадучись 15, вода 10, лестница вверх 8 / вниз 4, прыжок 8, падение 8 + 2 за блок; урон падения —
по 1 за блок выше 2 (падение на 2 безопасно, на 3 ранит). Осторожный шаг запрещён при обрыве глубже 2,
заглядывание — 8 клеток пути. Расходные блоки для засыпки и мостов (установка 5 тиков, ценные — 20):
земля, булыжник, гравий, песок и любые доски (`*_planks`). Стоимости решают порядок целей
(ближняя-дешёвая первая) и «ломать или обходить», ванильный поиск пути не перестраивают.

Как скрипты движения работают в игре:

- `return_home` идёт к дому духа; дом ставит команда `/spirit home <духи> set [x y z]` (без координат — на месте духа),
  снимает `/spirit home <духи> clear`; дом хранится в NBT духа (`SpiritHome`). Дома нет — `FAILED` «дом не задан»
  до первого шага.
- `set_camp` ставит лагерь похода (`x/y/z` необязательны — без них на месте духа, отсутствующие оси берутся
  от позиции духа; `radius` необязателен, по умолчанию 16); `clear_camp` снимает лагерь. Лагерь хранится в NBT
  духа (`SpiritCamp`: точка, радиус, владелец) рядом с домом и переживает перезапуск. Итог `set_camp` —
  `Data` (`camp: true`, `x/y/z`, `radius`); `clear_camp` — `Data` (`camp: false`). Команда `/spirit camp <духи> set [x y z]`
  и `/spirit camp <духи> clear` делает то же без скрипта. Отход `HOME` (скрипт `retreat` и тактика) идёт к ближайшей
  из дома и лагеря; нет обеих точек — `FAILED` «точки отхода нет». Точка обороны поселения — ближайшая из дома
  и лагеря к духам.
- `goto_block` просматривает радиус порциями (до 4 срезов за тик), берёт `count` ближайших блоков по стоимости пути
  и идёт, пока любой из них не окажется в досягаемости 4.5 от глаз; блоков нет — `FAILED` «блоков вида X в радиусе R нет».
- `come_to_player` без имени идёт к ближайшему игроку; игрока нет — `FAILED` до первого шага.
- `patrol` проходит точки по порядку; недостижимая точка (дух упёрся и не двигается 40 тиков) пропускается навсегда и
  считается; круг закончен — `SUCCEEDED`, все точки недостижимы — `FAILED` с числами «прошёл N из M точек».
- `wander` выбирает точки по сиду духа в радиусе от старта на твёрдом полу без опасных соседей, до истечения времени.
- `keep_distance` не заканчивается, пока цель жива: раз в 10 тиков сравнивает расстояние с `distance`; дальше
  `distance + 1` — подходит, ближе `distance` — отходит. Цель — имя игрока или UUID сущности.
- `walk_careful` идёт как `goto`, но при каждом построении пути отказывает, если путь не доходит до цели или в
  ближайших 8 клетках есть спуск глубже 2 блоков; дух при отказе стоит. Ванильный поиск пути и так не спускается
  глубже `MAX_DROP`, поэтому осторожный шаг отличается быстрым отказом «недостижимо осторожным шагом» вместо
  застревания у края.
- `step_over` шагает на соседнюю клетку на той же высоте или на 1 выше, если на ней можно стоять; иначе `FAILED` без движения.
- `climb` (`down`, по умолчанию false) лезет по ближайшей колонне из лестниц, лиан или строительных лесов
  (`minecraft:climbable`): без `down` — до верхней ступени, с `down=true` — до нижней. Колонна ищется в клетке
  духа и у четырёх соседей на его высоте; если дух стоит не в колонне (например, на площадке у её верха),
  скрипт сперва подходит к ней вплотную. Колонны рядом нет — `FAILED` «рядом нет лестницы, лианы или
  строительных лесов». Подъём и спуск идут подъёмом вверх/вниз по ступеням без строительства блоков; итог —
  направление, число пройденных блоков и достигнутый `y`.
- `approach` выбирает стоянку (`StandChoice`) и идёт к ней; если путь к стоянке не удался, пробует следующую (до 3);
  стоянки нет — `FAILED` «подойти некуда».

Скрипты склада (`deposit`, `withdraw`, `sort_chest`, `unload`) ищут контейнер в радиусе (`radius`, по умолчанию 8).
Параметр `container` принимает `"nearest"` (ближайший допустимый), координаты `"x,y,z"` и `"auto"`. При `"auto"`
дух сам выбирает сундук под предмет: сначала тот, где уже лежит неполная стопка этого предмета (ближайший из
таких), затем тот, где этот предмет есть и остался свободный слот, затем ближайший со свободным слотом; некуда —
понятный отказ с числами. Нестакующиеся предметы (инструменты, броня) идут в сундук, где лежат такие же, иначе в
ближайший свободный. У `unload` значение по умолчанию — `"auto"` (вернувшись из шахты, дух докладывает
стакующиеся предметы к существующим стопкам), у остальных — `"nearest"`.

Скрипт `eat` съедает еду из инвентаря: с названным `item` — именно её, без него — лучшее по питательности
из таблицы еды; еды нет — `FAILED` с причиной.

Скрипты стройки и земляных работ (`place_block`, `pillar_up`, `pillar_down`, `fill`, `clear_area`, `dig_area`, `dig_descent`,
`dig_descent_widen`, `place_descent_stairs`, `safe_mine`, `build_schematic`, `build_farm`, `build_fence`, `build_shelter`, `light_area`):
ставят и ломают блоки порциями по одному за тик, снизу вверх. Материалы — только из инвентаря духа;
нехватка — `FAILED` с числами (`have`/`missing`), автоматической закупки нет. Свои поставленные блоки дух
помечает и может разобрать; постройка игрока защищена. Лимиты: сторона куба `dig_area` 1..16, объём
`fill`/`clear_area`/`dig_area` не больше 4096, схема не больше 32³ и 4096 блоков; превышение отвергается
до первого изменения мира.

- `place_block` (`block`, `x`, `y`, `z`) — поставить один блок. Отказы с причиной: место занято, нет опоры,
  далеко (подходит сам, недостижимая стоянка — `FAILED`), защищено, нет материала («нужно 1, есть 0»).
- `dig_out` (`x`, `y`, `z`) — выбраться из-под земли к точке: лестница вверх (ступень 1, проход 2 высоты) в сторону
  точки, пустой пол ступени — булыжником из инвентаря; конец — дух под открытым небом или на высоте точки. Доска
  сама запускает его замурованному духу (воздуха к поверхности нет) с целью «дом» и показывает «Выбирается из-под земли».
- `pillar_up` (`height`, `block`, `down`) — подняться столбом на `height` блоков (1..256): дух прыгает и ставит блок
  под себя, свои блоки помечает (как `dig_descent`). `block` необязателен: без него берётся дешёвый материал из
  инвентаря (земля, затем булыжник). `down=true` после подъёма сразу разбирает столб и возвращает блоки в инвентарь.
  Перед опасностью (лава или вода в клетке/рядом, потолок, нехватка материала) останавливается с причиной,
  ничего не ломая; итог называет высоту, а при `down` — сколько блоков вернулось.
- `pillar_down` — разобрать свой столб под духом сверху вниз и вернуть блоки в инвентарь. Своих помеченных блоков
  нет — `FAILED` «под духом нет своего столба». Полный инвентарь — лишние блоки выпадают рядом, число названо в итоге.
- `fill` (`block`, `x1..z2`) — залить коробку (углы в любом порядке). Ячейки духа ставятся последними;
  если коробка не выпускает духа — сначала выходит наружу, иначе колонка пропускается с записью в итог.
- `clear_area` (`x1..z2`) — убрать ломаемое; неразрушимое, защищённое и небезопасное (рядом жидкость,
  опора под ногами) пропускается со счётчиком; если не убран ни один — `FAILED` с числами. Дроп подбирается.
- `dig_area` (`x`, `y`, `z`, `size`) — то же, но куб со стороной `size` от минимального угла.
- `dig_descent` (`direction`, `y`) — спуск в шахту вниз лесенкой в сторону `north`/`south`/`east`/`west` до этажа
  `y` (−64..319, по умолчанию −58). Шаг — колонка из трёх клеток: на этаж ниже и на блок ближе по направлению.
  Перед опасностью (пол или подпол не твёрдый, жидкость в проходе или боковой стенке) останавливается без
  копания: `result.reason` называет блок и клетку, `reached=false`. На ступенях через интервал из данных
  (`data/theminespirit/mining/descent.json`, по умолчанию 4) ставятся факелы из инвентаря духа.
- `dig_descent_widen` (`direction`, `y`) — расширить существующий спуск уровня 1 до тоннеля шириной 3 и высотой 6
  блоков по всей длине до рабочего этажа y (данные уровней — файл descent_levels.json). Идёт по колонкам уровня 1;
  перед опасностью (лава/вода в клетке расширения, нетвёрдый пол боковой полосы) останавливается без копания,
  result.reason называет блок и клетку, reached=false. Факелы уровня 1 сохраняются; итог — как у `dig_descent`.
- `place_descent_stairs` (`direction`, `y`) — поставить ступеньки на двух полосах существующего спуска (третью,
  центральную, оставляют под будущие рельсы — уровень 4). Каменные ступеньки кладутся по одной за тик снизу вверх,
  материал — из инвентаря духа; итог называет reached, y, depth, blocks_placed, reason.
- `safe_mine` (`mode`, `direction`, `y`, `length`, `torchInterval`) — пройти безопасную шахту шириной один блок.
  `mode` = `staircase` — спуск лесенкой вниз до этажа `y` (по умолчанию из `descent.json`): колонка ступени
  копается в три клетки (две на духа и одна над головой, иначе дух упрётся в потолок следующей ступени);
  `mode` = `tunnel` — горизонтальная штольня длиной `length` блоков в две клетки высоты. Пол под ногами и
  боковые стенки с лавой или водой дух закладывает блоком из инвентаря (булыжник, земля, доски, песок),
  провал под ногами останавливает проходку (reached=false, причина называет клетку), сыпучий блок (гравий,
  песок) над головой сперва падает, и только потом его выкапывают — под падающий блок дух не заходит.
  Факелы ставятся каждый `torchInterval`-й шаг (по умолчанию из `descent.json`). Итог: reached, y, depth,
  blocks_dug, blocks_filled, torches, reason.
- `build_schematic` (`file`, `x`, `y`, `z`, `rotation`, `segments`) — постройка по текстовому файлу слоёв
  `data/theminespirit/schematics/<file>.txt` (формат — ниже, «Файл постройки»), якорь в `x,y,z`, поворот
  `none`/`clockwise_90`/`clockwise_180`/`counterclockwise_90`. Дух сначала очищает клетки `.` и чужие блоки в
  клетках схемы (защищённое не трогает), затем ставит блоки снизу вверх всё, до чего дотягивается со стоянки
  (3 по горизонтали, 15 вверх, 3 вниз — `building/build.json`), примерно 2 блока в секунду со взмахом руки и
  звуком; двери и калитки — последними и снаружи. Уже стоящие нужные блоки пропускаются без расхода; дверь и
  кровать — один предмет на обе клетки. `SUCCEEDED` — только когда каждая клетка совпала со схемой, иначе
  `FAILED` с числом несовпавших клеток и причиной. Ошибка формата останавливает старт громко.
