### GET /v1/health

Лёгкая проверка живости серверного тика для сторожа зависания. Ответ не ходит в серверный поток и не читает мир,
поэтому отвечает, даже когда `/v1/bots` уже висит на задаче в тике.

```json
{"verdict":"ok","age_ms":421,"tick":24416800,"last_tick_ms":1800000000000,"threshold_ms":180000,"debug_paused":false}
```

| Поле | Что значит |
|---|---|
| `verdict` | `ok` — тик идёт; `hung` — тик стоит дольше порога; `debug` — держится замок живой отладки; `unknown` — тика ещё не было |
| `age_ms` | миллисекунды с последнего тика; `-1`, пока тика не было |
| `tick` | номер серверного тика |
| `last_tick_ms` | время последнего тика в миллисекундах UTC; `0`, пока тика не было |
| `threshold_ms` | порог зависания из `hangAfterSeconds` в `theminespirit-rest.toml` |
| `debug_paused` | замок `/opt/minecraft/debug.lease` держится (`live-debug.sh lock`) |

Порог по умолчанию — 180 секунд (`hangAfterSeconds`, допустимо 30–3600). Пока замок живой отладки держится,
`verdict` равен `debug`, даже если тик стоит: пауза на брейкпоинте — не зависание, сторож не перезапускает сервер.

Зависание (`hung`) — повод снять `jcmd <pid> Thread.print` и перезапустить сервер штатными `stop.sh`/`start.sh`.
Это делает `hang-watch.sh` по cron раз в минуту; строки о срабатывании — в `/opt/minecraft/logs/hang.log`, дампы —
`/opt/minecraft/logs/hang-<дата-время>.txt`. Файл-сердцебиение `/opt/minecraft/logs/tick.heartbeat` (pid, тик, время)
нужен сторожу, когда REST не отвечает вовсе.
