# Поведение агента: минимум рассуждений, полный анализ, явный техдолг

Читает любой агент (Claude, opencode, субагент) перед первой правкой в задаче. После прочтения он обязан
отвечать готовым результатом, доводить анализ до корневой причины и заканчивать каждый ответ разделом
«📌 Технический долг». Карта правил — [AGENTS.md](../AGENTS.md); как писать тексты — [docs/WRITING.md](WRITING.md).

## Минимум рассуждений

- Выдавай сразу готовый код или итоговый результат. Рассуждения допускай только в крайнем случае и строго
  не более 1–2 предложений.
- Не излагай chain-of-thought: не показывай «сначала думаю…, потом проверю…», не пересказывай шаги решения,
  если пользователь явно не попросил разбор.
- Начинай ответ с результата. Запрещены вступления, планы «что сейчас сделаю», извинения, самопохвала,
  перечисление промежуточных шагов и ход отладки.
- Экономь контекст: codegraph вместо перечитывания файлов, точечные правки Edit, вывод команд ≤ 40 строк,
  полный лог — в файл.
- Прочитанный файл не перечитывай: запомнил один раз — дальше работай по памяти.

## Внутренний чеклист перед ответом

Прогоняй мысленно, в чат не выводи. Не выдавай ответ, пока не пройдены все пункты.

1. **Задача понята целиком:** цель, границы, чем считается «готово».
2. **Корневые причины найдены все:** не симптом, а причина; каждая подтверждена `file:line` или данными.
3. **Граничные условия проверены:** пусто, ноль, максимум, повтор, отказ, параллельный вызов.
4. **Контекст проверен до конца:** кто вызывает, что сломается, какие правила и документы действуют.
5. **Недоделок нет:** нет заглушек, «потом», обходов архитектуры ради зелёного прогона.
6. **Доказательства есть:** каждый факт — выводом команды, хэшем коммита или `file:line`. Нет доказательства —
   назови, чего не хватает, и не выдавай догадку за факт.

## Раздел «📌 Технический долг» — в каждом ответе

- Заканчивай каждый ответ пользователю разделом «📌 Технический долг». Без исключений.
- Есть долг — назови: что, где (`file:line` или путь), почему плохо, как убрать, объём работы.
- Долга нет — напиши дословно: `Технический долг: отсутствует`.
- Мелкий долг (мёртвый код, дубль, неточное имя, лишний лог, пропущенный тест) правь сразу в той же задаче.
  Крупный (переделка класса или модуля, обход архитектуры, сторож без теста) не трогай — опиши в разделе.
- Промолчать о замеченном долге — ошибка агента. Не уверен, долг это или норма, — проверь по правилам
  задачи и назови сомнение явно.

## Выдача кода и правок

- Выдавай рабочий и полный код: без заглушек, многоточий и «остальное без изменений».
- Правь существующие файлы точечным Edit, не переписывай файл целиком.
- Имена — по-английски; комментарии — только «почему», без пересказа «что делает».
- Не добавляй обработку невозможных случаев и флаги совместимости, которых не просили.

## Порядок работы

- Сначала прочитай правила задачи и связанные классы, потом пиши код; правила по красным прогонам не учи.
- Чини причину, а не следствие ([docs/FIXING.md](FIXING.md)); обходной путь — техдолг, назови его.
- Тесты — только `scripts/test.sh unit` или `gametest`; красный прогон не коммитится ([docs/TESTING.md](TESTING.md)).
- Коммить по правилам [docs/GIT.md](GIT.md); тема коммита — `feat`, `fix`, `test`, `refactor`, `docs`, `chore`.
- Работай в ветке `main` клона `the-mine-spirit/`; worktree и отдельные ветки не создавай.
- Публикацию мода и перезапуск сервера делай только по согласованию с пользователем.
- Не завершай процессы Gradle и Java других агентов (`kill`, `taskkill`, `--stop`); поиск по всему диску запрещён.
- Язык общения, документации, коммитов, assertion и логов — только русский; имена в коде — английские.

## Формат ответа

- Результат — одно-два предложения; факты — по строке на факт; в конце — «📌 Технический долг».
- В ответе — только то, что нужно пользователю: результат, доказательства, остаток работы.
