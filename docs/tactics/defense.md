## Оборона поселения

Слой единого тактического интеллекта, внутри того же тика координатора
(`SpiritCoordinator` владеет `neoforge/defense/DefenseService`, один на поселение):
отдельного цикла, снимка и реестра нет, интервал — `SNAPSHOT_INTERVAL_TICKS` (10) координатора.
На каждом тике: защитники из членов поселения (`DefenderReader`: позиция, доля здоровья, броня
не выше 20, лук, ближний урон в секунду, лечилка; выбывших и занятых задачей пропускает),
враги — `EnemyCollector` (один запрос, факты общие с интеллектом), заряженные криперы —
резолвом по id (`level.getEntity`, не скан), план — `DefensePlanner.plan` (сектора по силе
направлений, специализации лучник/мечник, цели по `priorities.json`, инстинкты поверх цели,
передача цели раненым), приказы — `DefenseDirectives` (пост без цели — `GUARD_AREA` на посту;
цель — `AGGRESSIVE` с навязанным id врага; отход/лечение и мечник против заряженного —
`PASSIVE` с точкой обороны). Применение — оверлеем поверх `CoordinatorDirectives` в том же
`applyPlan` (гистерезис по равенству приказа и навязанной цели): посты — `setGuardZone`,
цель — `setForcedTarget` (селектор конкретного моба не адресует, id едет отдельным полем),
зона держится и у атакующих. Помощь атакованному остаётся у `AssistPolicy` 31: приказ обороны
помощника не перезаписывает. Раз распределение взвешенное, при угроз уже защитников посты
схлопываются на угрожаемом секторе (квоты ядра) — равные сектора 31 действуют без угроз.
Прямое присутствие угрозы рядом с защитником — не бой: `AssistPolicy` зовёт неатакованного
(`threatsNear` не проверяется — передовые посты всегда в радиусе угроз), атакованный держится сам.
Бюджеты: один запрос сущностей и один план на пересборку; укрытия (`BlockerProbe`) — не больше
`BLOCK_BUDGET` (24) чтений блоков и только для `COVER_ENGAGE`; между пересборками мир не читается.
Ритм «ударил–отошёл» и дистанцию до крипера ведёт сам движок тактики
(`explosive_strike_retreat`, рефлекс `ExplosionAvoidance` выше приказов).

## Командная оборона: отряды, помощь и рассредоточение

Когда защитники стоят не кучей, а отрядами (пары в шеренге, посты по периметру), `DefensePlanner` зовёт
`TeamDefensePlanner`: отряды собираются по расстоянию, ёмкость считается из здоровья, брони, оружия и сытости,
нехватку закрывают ближайшие свободные отряды, а сбежавшийся в точку отряд расходится по угрожаемым секторам.
Веса — `data/theminespirit/tactics/defense.json` (горячая таблица `defense`), кейсы — `TeamDefense*ScenarioTests`
(шеренга владельца, круг по площадям этапов, мобы, экипировка, зелья, стягивание и рассредоточение).
