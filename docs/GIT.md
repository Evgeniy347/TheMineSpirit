# Git

## Коммит

- Коммит — законченный блок работы (подсистема, чеклист, группа исправлений), а не каждый шаг. Без мусора:
  перед коммитом `git status --short`, после — `git log -1 --stat`.
- Агент коммитит сам. **Push — только по прямой просьбе пользователя.**

## Сообщение коммита

- Формат: `<тип>: <описание по-русски>`; типы `feat` (поведение), `fix` (ошибка), `test` (только тесты, в том числе
  только GameTest), `refactor`, `docs`, `chore` (сборка, скрипты). `feat:`/`fix:` с production-кодом обязан менять и
  тесты. Формат и правило про тест проверяет хук `commit-msg`.
- Хук `pre-commit` гоняет `scripts/test.sh unit --changed`, если в коммите есть `src/` или сборка;
  красный — отказ. `--changed` берёт только затронутые модули и `:guards`; полный `unit`, опыт запуска сервера
  (`scripts/testing/check-start.sh`) и GameTest — приёмка в финале исполнителя и перед слиянием (`scripts/lead/chkq.sh`).
  SpotBugs и PMD (сотни секунд) — не в хуке.
  Хуки подключает `scripts/install-git-hooks.sh`. `--no-verify` и отключение хуков (`-c core.hooksPath=…`) —
  только по прямому указанию пользователя.

## Запрещённые команды

Уничтожают незакоммиченную работу или историю: `git stash`, `git reset --hard`, `git clean`, `git checkout`/`restore`
без пути (и с путём — к чужим правкам), `git commit --amend`, `rebase` (кроме финала ветки), любая перезапись коммитов.
Ошибка исправляется новым коммитом. Посмотреть закоммиченное: `git show HEAD:путь`.
Запрет держат хуки `reference-transaction` (ветка только растёт) и `pre-rebase`
(проверка — `scripts/testing/check-history-hooks.sh`).

## Удаление файлов

Удалять только своё, проверив путь. Удаление — одним коммитом со всеми ссылками на файл (README, AGENTS.md, docs).

## Ветки и worktree (владелец 11.11)

Работа — прямо в `main`. Отдельная ветка, git worktree или исполнитель — только по согласованию с владельцем;
тогда действует «Финал ветки».

## Финал ветки (владелец 12.10)

1. Исполнитель на своей ветке `task/*`: `git rebase main` (конфликты — по смыслу).
2. Там же: `scripts/test.sh unit` и GameTest (приёмка — 3 полных прогона подряд), итог — в отчёт.
3. Главный агент принимает ветку на сервере (`docs/LEAD-AGENT.md` → «Приёмка»): слияние с текущим main в
   проверочном worktree, unit и полный GameTest, затем `git merge --no-ff` в main и `git push backup main`.
