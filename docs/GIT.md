# Git

## Коммит

- Одно логическое изменение — один коммит. Без мусорных файлов.
- Агент сам решает, когда и как коммитить, без отдельного разрешения. **Push — только по прямой просьбе
  пользователя.**
- Большую задачу дроби на несколько коммитов по мере готовности логических частей: не копи всё в один
  коммит к концу. Готовая и проверенная часть коммитится сразу.
- Перед коммитом: `git status --short` — в коммит не попадают временные файлы, логи, `build/`, `run/`.
- После коммита проверь `git log -1 --stat`: в коммите ровно то, что ты собирался закоммитить.

## Сообщение коммита

Формат: `<тип>: <краткое описание на русском>`

| Тип | Когда |
|---|---|
| `feat` | новая функциональность или изменение существующей |
| `fix` | исправление ошибки |
| `test` | только тесты |
| `refactor` | изменение структуры без изменения поведения |
| `docs` | только документация и инструкции |
| `chore` | сборка, скрипты, настройка репозитория |

Примеры: `feat: добавлен блок духа шахты`, `fix: дух не исчезал при выгрузке чанка`.

Если коммит удаляет комментарий с объяснением «почему», тело коммита называет, где этот смысл теперь
(тест или новое имя) — см. CONVENTIONS.md → «Комментарии».

## Запрещённые команды

Эти команды уничтожают незакоммиченную работу без возможности отката:

- `git stash`;
- `git reset --hard`, `git clean`;
- `git checkout` / `git restore` без конкретного пути (и с путём — к чужим незакоммиченным правкам);
- `git commit --amend`, `rebase` и любая перезапись уже существующих коммитов. Ошибочный коммит
  исправляется новым коммитом поверх.

Посмотреть закоммиченную версию файла, ничего не трогая: `git show HEAD:путь/к/файлу`.

## Удаление файлов

- Удалять только то, что создал сам, проверив точный путь.
- Удаление файла идёт одним коммитом вместе со всеми ссылками на него (README, AGENTS.md, docs).
