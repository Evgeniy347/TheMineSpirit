# Git

## Коммит

- Одно логическое изменение — один коммит. Без мусорных файлов.
- Агент сам решает, когда и как коммитить, без отдельного разрешения. **Push — только по прямой просьбе
  пользователя.**
- Большую задачу дроби на несколько коммитов по мере готовности логических частей: не копи всё в один
  коммит к концу. Готовая и проверенная часть коммитится сразу.
- Перед коммитом: `git status --short` — в коммит не попадают временные файлы, логи, `build/`, `run/`.
- После коммита проверь `git log -1 --stat`: в коммите ровно то, что ты собирался закоммитить.

## Сообщение коммита

Формат: `<тип>: <краткое описание на русском>`

| Тип | Когда |
|---|---|
| `feat` | новая функциональность или изменение существующей |
| `fix` | исправление ошибки |
| `test` | только тесты |
| `refactor` | изменение структуры без изменения поведения |
| `docs` | только документация и инструкции |
| `chore` | сборка, скрипты, настройка репозитория |

Примеры: `feat: добавлен блок духа шахты`, `fix: дух не исчезал при выгрузке чанка`.
Сборка, Gradle, скрипты — это `chore`, отдельных типов `build`/`scripts` нет.

Коммит `feat:`/`fix:`, меняющий production-код (`src/main/java`, кроме GameTest), обязан в том же коммите
менять и тесты (`src/test/java` или GameTest): поведение без теста не защищено. Коммит, меняющий только
GameTest, — это `test:`, даже если правка родилась из исправления: GameTest лежит в `src/main/java`, но это тест.

Формат и правило про тест проверяет хук `scripts/git-hooks/commit-msg`; после клонирования подключи его:
`scripts/install-git-hooks.sh`. Обходить хук (`--no-verify`) запрещено.

Хук `scripts/git-hooks/pre-commit`: если в коммите есть изменения в `src/`, `build.gradle`, `gradle.properties` или
`settings.gradle`, он прогоняет `./gradlew test` и отклоняет коммит при красном (красный коммит ломает бисекцию и
`scripts/prove-red.sh`). Документы, скрипты и слияния — без прогона. Тесты читают рабочее дерево, а не индекс:
незастейдженные правки в `src/` участвуют в прогоне, хук об этом предупреждает.

Если коммит удаляет комментарий с объяснением «почему», тело коммита называет, где этот смысл теперь
(тест или новое имя) — см. CONVENTIONS.md → «Комментарии».

## Запрещённые команды

Эти команды уничтожают незакоммиченную работу без возможности отката:

- `git stash`;
- `git reset --hard`, `git clean`;
- `git checkout` / `git restore` без конкретного пути (и с путём — к чужим незакоммиченным правкам);
- `git commit --amend`, `rebase` (кроме финала ветки задания — ниже) и любая перезапись уже существующих коммитов. Ошибочный коммит
  исправляется новым коммитом поверх.

Посмотреть закоммиченную версию файла, ничего не трогая: `git show HEAD:путь/к/файлу`.

Запрет проверяют хуки `scripts/git-hooks/reference-transaction` (ветка может только расти вперёд — ловит
`--amend`, `rebase`, `reset` назад, `branch -f`; `stash` отклоняется) и `pre-rebase`. `--no-verify` их не обходит.
Отключать хуки (`-c core.hooksPath=…`) может только пользователь.

## Удаление файлов

- Удалять только то, что создал сам, проверив точный путь.
- Удаление файла идёт одним коммитом вместе со всеми ссылками на него (README, AGENTS.md, docs).

## Финал ветки: rebase на main

Решение владельца (12.10). Перед финальным прогоном ветка задания переносится на текущий main, тесты гоняются уже
на перенесённой ветке, и main сдвигается на неё перемоткой — после этого ничего дополнительно не гоняется.

1. Исполнитель, стоя на своей ветке `task/*`: `git rebase main` (конфликты — по смыслу, `git rebase --continue`).
2. Там же: `./gradlew test` и GameTest (приёмка — 3 прогона подряд), итог — в отчёт.
3. Главный агент: `git merge --ff-only task/<имя>` в main. Если main за это время ушёл вперёд — шаги 1–2 повторяются.
   Исключение: если main ушёл вперёд только коммитами без `src/`, `build.gradle` и `gradle*` (документы, скрипты
   надзора), достаточно повторить rebase — тесты проверяли тот же код.

Хуки разрешают переписать только ветку `task/*` и только во время rebase, когда новая вершина содержит main
(`scripts/git-hooks/pre-rebase`, `reference-transaction`; проверка — `scripts/testing/check-history-hooks.sh`).
main, чужие ветки, `--amend`, `reset` назад, `branch -f`, `stash` по-прежнему отклоняются.
