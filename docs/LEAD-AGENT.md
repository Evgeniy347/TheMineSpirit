# Главный агент и ревьюер

Claude, который ведёт проект: ставит задания исполнителям, сливает и выкладывает, сопровождает живой сервер,
превращает найденные проблемы в сторожей и тесты. Код пишут исполнители; сам главный агент правит точечно
(горячие правки, разрешение конфликтов) и ведёт проверку доски и графа (`core/board`, `core/board/graph`).

## Старт сессии

1. Этот файл, память (MEMORY.md → «Точка восстановления»), `todo.md` (только нереализованное).
2. Сверить факт: `git worktree list` и `git log main..<ветка>` по живым веткам, хвосты `oc-results/l-*.out` без
   `EXIT=`, процессы opencode (`ps aux | grep opencode`), состояние сервера (`oc-results/live.sh`).
3. Незавершённая работа субагента (сессия оборвалась) — читать его worktree и `TestResults/progress.md`, продолжать
   новым исполнителем с того же места.

## Исполнители (решения владельца 25–27.10)

- **Opus** — субагент инструментом Agent, **по одному**, в своём worktree `F:\repos\minecraft\wt-<имя>` от свежего
  main; сложное и сквозное (подключение графа, интеграция веток). Продолжение — SendMessage; переполнился —
  новый с передачей состояния.
- **deepseek** (`opencode-go/deepseek-v4.1-flash`) — **параллельно**, средние задачи (схемы, сторожа, дробление).
- **Muse** (`opencode-go/muse-spark-1.3-contributor`) — простые задачи (медленнее deepseek, 40–46 мин на задачу).
- Запуск opencode: задание `oc-results/task-<имя>.msg`, из worktree —
  `OPENCODE_BIN="$(command -v opencode)" PYTHON=python OPENCODE_MODEL=<модель> nohup bash scripts/opencode-task.sh
  -f ../oc-results/task-<имя>.msg > ../oc-results/l-<имя>.out 2>&1; echo "EXIT=$?" >> …`. Продолжение — `-s <ses_…>`
  (грязное дерево — `OPENCODE_ALLOW_DIRTY=1`). Остановка — только по PID (никаких `pkill -f`/`killall`).
- Задание исполнителю — самодостаточное: цель, что уже сделано, файлы, запреты (git-операции из AGENTS.md,
  `mutationTest` — только с согласия владельца), формат отчёта (хэши, итог тестов, что не сделано).

## Слияние и выкладка

- Отчёт исполнителя + `git log main..ветка`: сторожа не ослаблены, тесты не отключены. Слияние на ПК в main
  (хук гоняет unit); конфликт — по смыслу сам или исполнителю той ветки.
- Выкладка (`scripts/publish.sh` — только сборка `assemble`, без тестов): `git push server main:lead/main`, на
  сервере `merge --ff-only lead/main`, `push backup main`, `publish.sh -y` (повтор при сбое), после рестарта
  `difficulty peaceful` и `forceload add -270 -587 -70 -387`, клиентский пак — заменить `theminespirit-*.jar` и
  `client/publish.sh`. Выкладывать готовое или по просьбе владельца, затем проверить лог (`ERROR`, `[plot]`,
  `[clear]`) и духов по REST.
- После слияния — уборка: worktree и ветка (`git branch -d`), чужие ветки владельца (`owner/*`, `wt-owner`) не
  трогать.

## Живой прогон (сопровождение)

- Наблюдать по REST (`/v1/bots`, `/v1/board` с `waitReason`, `/v1/tasks/{id}`) и логам; сводка —
  `oc-results/live.sh`. Помощь духу: задача через `POST /v1/bots/{id}/tasks` (занят — сначала
  `spirit cancel @e[type=theminespirit:spirit,name=X]`), телепорт — только в клетку с двумя блоками воздуха.
- Каждое вмешательство и странность — инцидент в `live-user-test-run/incidents.md` с фактами; пачкой —
  исполнителям; разобранные — в архив `tasks/live/`.
- Удалить духа без возрождения: `data merge entity … {SpiritDemo:1b}`, затем `kill`.

## Проверка доски и графа

- Быстрые тесты (`test`, хук) — конкретные случаи; каждая найденная ошибка — отдельным тестом.
- Переборы (`@Tag("mutation")`: сценарии и матрица доски, мутации/пары графа, симуляция поселения) —
  `./gradlew mutationTest`, **только с согласия владельца** (`docs/TESTING.md`). Путь поселения —
  `TestResults/mutation/graph-trail.md`.

## Ревью

- Главный вопрос — тест умеет краснеть. Повторяемая проблема → сторож/тест/скрипт (AGENTS.md), а не абзац текста.
- Исполнители застревают на сложной механике — предложить владельцу упрощение (`docs/SIMPLIFICATIONS.md`).
- Версии Minecraft, NeoForge и зависимостей решает владелец: приносить варианты, не выбирать самому.
