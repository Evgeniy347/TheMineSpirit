# Модели-исполнители opencode

Какую модель ставить на задание. Только бесплатные `opencode/*-free` и `opencode/big-pickle`;
`opencode-go/*` идут через платную подписку — не использовать. Модель задаётся
`OPENCODE_MODEL=opencode/<модель> scripts/opencode-task.sh …`.



## Модели моста deepseekbridge (решение владельца 16.10)

Мост владельца на ПК (`deepseekbridge/…`, только ПК): `deepseek-web`, `qwen3.7-plus-web`, `qwen3.8-max-web`,
`qwen3.8-omni-flash-web`. Лимиты бесплатного провайдера opencode их не задевают.

- **Одновременно не больше двух:** один `deepseek-web` и один любой `qwen*-web`. Второй экземпляр той же модели и
  два разных qwen одновременно не запускать.
- Контекст у всех — около 1 млн токенов, но через мост в opencode не пробрасывается (в `opencode models` лимит 0):
  opencode их не сжимает. Подходят для больших задач; задание и прогресс всё равно в `TestResults/task.md`/`progress.md`.
- Запуск — как обычный исполнитель ПК (docs/LEAD-AGENT.md → «Где работают исполнители»), `OPENCODE_MODEL=deepseekbridge/<модель>`.
- Мост может давать аномалии (обрезанные аргументы, вызов инструмента текстом): остановить, коротко с примером описать
  владельцу, после починки — новая сессия.

## Контекст моделей и сжатие (замер 15.10)

| Модель | Контекст | Сжатий за большую задачу |
|---|---|---|
| mimo-v2.6-flash, big-pickle | 200 тыс. (big-pickle — ввод 160 тыс.) | 2–12: сессия набирает 100–190 тыс. за 20–60 шагов |
| muse-spark-1.3, longcat-2.5 | ~1 млн | 0 |
| deepseekbridge/deepseek-web | не указан (0): opencode не сжимает, что делает веб-чат — не видно | — |

При сжатии opencode заменяет разговор сводкой и пишет «Continue if you have next steps…» — подробности задания и
сделанного теряются, модель кружит (28 у mimo: 12 сжатий, часы на одном тесте). Поэтому:
- большие задачи (чеклист, несколько частей, долгая отладка) — muse и longcat; mimo и big-pickle — короткие, на один пункт;
- надзор (`scripts/opencode-task.sh`) кладёт задание в `TestResults/task.md` (правки по ревью дописываются), исполнитель
  ведёт `TestResults/progress.md`; после сжатия надзор останавливает ход и продолжает сессию с напоминанием перечитать
  оба файла (строка «сжатие контекста» в failures.log);
- логи сборок и тестов — в файл, на экран только grep/tail ≤ 40 строк (правило в памятке исполнителя).
