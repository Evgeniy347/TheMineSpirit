# Переход «всё через граф»: пофайловый план

Дополнение к [graph-inputs.md](graph-inputs.md) (решение владельца 02.11). Цель: ни один сторож/алгоритм не
ставит работу и не решает «что важнее»; он только читает мир и отдаёт факты. Задачу, пару «дух → работа» и вес
выбирает граф. Ниже — каждый источник, его вход, заменяющий узел/путь и что удаляется.

Ориентиры объёма: слой доски ≈27.5 тыс. строк в 276 файлах (оценка владельца); ядро графа ≈2.5 тыс. строк
(18 Java-файлов, с Python-моделью ≈50); 50 файлов мимо графа ≈10.8 тыс., из них 23 `*Watch` — 3946 строк по
замеру. Реалистично уйдёт **≈6–7 тыс. строк**: остальное — чтение мира, аудит, исполнители действий и защита,
которые остаются, но перестают быть источником задач. Оценки в таблице — строки к удалению, не размер файла.

## Как проверять каждый шаг (критерий приёмки)

Исполнитель (deepseek) не закрывает шаг по «похоже, работает». Порядок:

1. **Красный тест по существу.** Новый unit/GameTest или ожидаемый файл сверки добавлен до правки; прогон
   `scripts/test.sh unit --tests <фильтр>` (или GameTest сцены) красный, код компилируется.
2. **Java-зелёный.** После правки — тот же фильтр зелёный; затем полный unit (перед коммитом) и GameTest пачки.
3. **Выгрузка.** `./gradlew graphExport` пишет `TestResults/graph-export/{graph,conformance}.json` на текущем HEAD.
4. **200/200.** `cd tools/graph-gpu && PYTHONIOENCODING=utf-8 py -3.9 test_conformance.py` — набор заданий,
   `feasible`, `chance` точно, `priority` ±1. Если добавлены пары «дух → работа», экспорт пишет `pairs.json`,
   отдельный `test_pairs.py` сверяет 200/200 пар.
5. **Симуляция.** `sim_gpu.py` повторяет `GraphSimulationTests.simulate_Baselines_WriteTrailReport`: этап, id,
   priority, шаги и тики на 5 базовых мирах `GraphMutations.baselines()`. Любое расхождение — либо баг, либо
   запланированное изменение; второе фиксируется в `tools/graph-gpu/REPORT.md` и в задании шага.
6. **Веса.** `search.py` пересчитывает множители; `best-weights.json` и абсолютные значения переносятся в
   `board/graph.json`; после переноса снова 200/200 и симуляция. Ослаблять правила `GraphPlannerTests` ради
   зелёного запрещено.
7. **Живая проверка.** `scripts/dev-server.sh up` и `scripts/live-debug.sh --run run-live/<сцена>`: состояние
   на доске/в журнале совпадает с ожидаемым; копию гасят `scripts/dev-server.sh down`.

Шаг принят только при всех семи пунктах; иначе — правка в том же блоке, без перехода к следующему.
