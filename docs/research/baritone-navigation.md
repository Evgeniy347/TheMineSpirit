## Архитектура Baritone
| Слой | Как устроено | Файлы |
|---|---|---|
| A* | `AStarPathFinder` + `AbstractNodeCostSearch`: узлы `PathNode` в `Long2ObjectOpenHashMap`, двоичная куча, стоимость в тиках, `MIN_IMPROVEMENT=0.01`, `MIN_DIST_PATH=5` | `pathing/calc/*`, `calc/openset/BinaryHeapOpenSet` |
| Коэффициенты | 7 параллельных «лучших» путей с весами эвристики `{1.5, 2, 2.5, 3, 4, 5, 10}`; если путь не к цели, отдаётся лучший достижимый сегмент | `AbstractNodeCostSearch.COEFFICIENTS`, `bestSoFar` |
| Бюджет времени | проверка каждые 64 узла: `failureTimeout` (2000 мс), пока нет пути >5 блоков, затем `primaryTimeout` (500 мс); plan-ahead — 4000/5000 мс | `AStarPathFinder.calculate0`, `Settings` |
| Движения | enum `Moves`: 4 шага, 4 подъёма, 4 спуска, 4 диагонали, 4 паркура, `PILLAR`, `DOWNWARD`; стоимость каждого — функция мира и инвентаря | `pathing/movement/Moves`, `movements/*` |
| Цены | `ActionCosts` в тиках: ходьба 4.633, вода 9.091, лестница 8.511/6.667, спринт 3.564, падение по таблице, прыжок; ломка = твёрдость/инструмент, установка — надбавка | `api/pathing/movement/ActionCosts`, `MovementHelper` |
| Ломка/постановка | входят в цену хода, а не в отдельный поиск: `getMiningDurationTicks`, `costOfPlacingAt` | `MovementHelper`, `MovementTraverse/Ascend/...` |
| Вода/падение | плавание, падение в воду глубже, чем на сушу, лестницы/лианы | `MovementFall`, `MovementDescend`, `MovementPillar` |
| Кэш мира | `CachedChunk`: 2 бита на блок (`AIR/SOLID/WATER/AVOID`), 16×16×height; `CachedWorld`: регионы 512×512 блоков (32×32 чанка), запись на диск, очередь упаковки, обрезка по расстоянию | `cache/CachedChunk`, `cache/ChunkPacker`, `cache/CachedWorld` |
| Чтение мира | `BlockStateInterface`: загруженный чанк → кэш; `worldContainsLoadedChunk`, `isLoaded`; кэш читается и для незагруженных чанков | `utils/BlockStateInterface` |

| Исполнение | `PathExecutor`: проверка мира, таймаут хода 100 тиков, `maxCostIncrease=10`, `costVerificationLookahead=5`, пауза на границе чанков, backtrack | `pathing/path/PathExecutor` |

| Асинхронность | поиск в отдельном потоке; `CalculationContext(forUseOnAnotherThread)` с потокобезопасной копией чанков; отмена, если старт/мир разошёлся | `PathingBehavior.findPathInNewThread` |

## Сопоставление с нашим
| Наше | Что есть | Чего не хватает против Baritone |
|---|---|---|
| `PathNavigation` 32/512 | быстрый локальный поиск, 4–5 мс | жёсткая стена 32; нет сегментов и таймаутов |
| `RoutePlanner` (40 000) | ходьба/вода/лестница/падение/ломка/установка/столб; частичный путь; бюджет узлов | нет бюджета времени и раннего отказа; 1.2–1.6 с на недостижимой цели; 190–244 МБ мусора |
| `Approach` | ваниль → сеть троп → `RouteDetour`/`StuckRescue`; таймаут по дистанции | «длинный» A* без предела времени; телепорт `StuckTeleport` удаляется |
| `StandSpots`, `MineStepStands`, `ClearAreaSession` | локальный выбор стоянок/расчистка | нет общего плана и кэша мира |
| Память маршрутов | память пройденных маршрутов, обратный путь | нет кэша незагруженного мира и асинхронного поиска |

Наши боли и что берём:
| Боль | Baritone-решение | Что делаем |
|---|---|---|
| Недостижимая цель 1.2 с | `failureTimeout`, `bestSoFar`, `MIN_DIST_PATH` | бюджет времени + ранний частичный путь |
| Подъём на 6–8 | `PILLAR`/`ASCEND` с постановкой блока | у нас уже есть `PILLAR`; нужен исполнитель и цена как у Baritone |
| Ломание по пути | цена хода включает ломку | у нас есть; добавить проверку запаса/инструмента и таймаут хода |
| Возврат домой 100+ | plan-ahead, `Favoring`, сегменты, кэш | сегменты + тропы + бюджет; без кэша мир не загрузится впереди |
| Вода | отдельные движения и цены | у нас `RoutePlanner` умеет; нужен понятный режим «можно плавать» |
| Шахта | кэш + граница загруженного | сегменты до границы загруженного, затем кэш/локальный поиск |

## План внедрения блоками

1. **Бюджет времени и частичный путь (1 блок).** Дедлайн в `Approach`/`RouteDetour`: 500 мс primary,
   2000 мс failure, как у Baritone; ранний `bestSoFar`. Метрика: поиск/мс/узлы на духа.
2. **Цены и проверка ходов (1–2 блока).** Свести цены к `ActionCosts`; учесть инструмент/запас блоков; таймаут
   хода и `maxCostIncrease`, иначе исполнитель идёт по устаревшему пути.
3. **Сегментированный дальний путь (2–3 блока).** Сессия: считать сегмент до границы загруженного/по бюджету,
   выполнять, планировать следующий; склейка; `Favoring` прошлого пути, чтобы не возвращаться.
4. **Кэш мира (2–3 блока).** 2-битная упаковка клеток по чанкам, регионы 512×512, запись на диск, чтение
   незагруженного; без этого «далеко» невозможно. Сначала только память + loaded chunks, диск — позже.
5. **Асинхронность (2 блока).** Снимок чанков для чтения в отдельном потоке, отмена по смене старта/мира;
   локальные ходы и исполнение — на серверном потоке.
6. **Исполнитель (1–2 блока).** Столб, ломка, постановка, вода, проверка мира, пауза на границе чанков.
7. **Тропы (1 блок).** Граф пройденных маршрутов как быстрый путь для знакомых целей; физическая тропа —
   отдельно, только по решению владельца.

Порядок по цене/пользе: 1 (сразу убирает 1.2 с) → 2 → 3 → 6 → 4 → 5 → 7.

Владелец разрешил копировать файлы Baritone (публичный репозиторий, LGPL-3.0 устраивает). Каждый скопированный
или производный файл начинается одной строкой `// lib: Из Baritone (github.com/cabaletta/baritone, <путь>),
лицензия LGPL-3.0.`; тексты — `LICENSE-LGPL-3.0`, `LICENSE-GPL-3.0`; зависимость на Baritone не подключается.

### Порядок блоков

1. **Сделано:** A* и куча, `ActionCosts`, базовые цены ходов, цели, бюджет 500/2000 мс, сегмент до границы
   загруженного. Пакет `core.navigation`, без встраивания в духов.
2. **Кэш мира и precompute:** `NavBlockType` (2 бита), `NavChunk`, `NavRegion` 512×512, чтение незагруженного,
   `PrecomputedData`-аналог (canWalkOn/canWalkThrough в байтах). Тесты `NavCachedRegionTest`.
3. **Дальний путь:** `NavCutoffPath`, статический отрезок, plan-ahead, `Favoring` прошлого пути, склейка сегментов.
4. **Исполнитель:** `Movement*`-аналоги (состояние, ломка, постановка, вода, лестница), таймаут хода,
   проверка изменения мира; сюда же столб и копание вниз.
5. **Асинхронность:** снимок загруженных чанков, поиск вне серверного потока, отмена по смене старта/мира.
6. **Встраивание:** `Approach` — ваниль 32 → тропа → `NavAStarSession` с бюджетом; удаление телепортов.
7. **Тропы и физическая тропа:** граф пройденных маршрутов + след для обратного пути; физическая тропа — только
   по решению владельца.

### Духам не нужно

Клиентское и игроковое: `LocalPlayer`, `Minecraft`, `InputOverrideHandler`, `LookBehavior`, рендер пути и оверлеи,
GUI/чат/команды, `ElytraBehavior`, `WaypointBehavior`, инвентарь хотбара и `ToolSet` в клиентском виде,
`Process`-задачи (Mine/Farm/Build/Explore), `Favoring` мобов, nether-pathfinder. Из Baritone берём только расчёт
пути, цены, кэш и исполнитель, переписанные под серверные сущности и `core`.

## Ходьба без изменения мира (02.11)

- Навигация духов включается с `NavSettings.canBreak=false, canPlace=false`: доступны шаг, подъём/спуск,
  падение, прыжок через щель, диагональ, плавание и подъём в воде, лестницы/лианы; ломания/постановки/столба нет.
- `LevelNavWorld`: закрытые двери/калитки/люки проходимы (их открывает `PassageWalk` в `RouteWalk`); незагруженный
  чанк — `available=false`, не воздух. Расчёт пути чанки коридора подгружает сам (`NavigationTickets`,
  тикеты на поход, бюджет в `SpiritConfig`), и ждёт загрузку вместо «пути нет».
- `RouteDetour`/`DigOutRoute`/`StuckRescue` идут через `NavSegmentedSession` порциями 10 мс; сессия 2 с, общий
  предел 15 с; `RouteWalk` больше не ломает и не ставит блоки.
- Тесты: яма с тремя ступенями — выход; колодец без ступеней — «пути нет»; щель/вода/стена/спуск; 128+ сегментами;
  бюджет; сторож `NavigationReadOnlyGuardTests` запрещает в навигации `setBlock/destroyBlock/placeBlock`.
