# Живая отладка: своя копия сервера

Карта скриптов (что запускается, пример, где работает, меняет ли мир) — [scripts/README.md](../scripts/README.md).

## Как найти ответ в логах

```
scripts/logq.sh cell -181,68,-518 2      # кто, когда и зачем менял клетку: все форматы координат
scripts/logq.sh spirit spirit-1 --since 30m   # лента событий духа
scripts/logq.sh ticket <id>              # вся история задания, включая завершённые
scripts/logq.sh failures --since 1h      # что падает чаще и почему
scripts/logq.sh stuck                    # метки «не двигается» и спасения
scripts/live.sh spirit spirit-1          # состояние духа уже поверх базы логов
```

База — `logs/events.db` рядом с `latest.log`; загрузчик дочитывает JSONL и старые логи сам.
Если ответа нет в типизированных таблицах, ищите текстом: `scripts/logq.sh text "нет пути"`.

## Коротко: застрял дух, что делать

```
scripts/live.sh status                  # кто что делает, падает ли граф, частые сбои
scripts/live.sh spirit spirit-5         # журнал духа и карта блоков вокруг него
scripts/live.sh loops                   # какие задания падают снова и снова
scripts/dev-server.sh up                # своя копия живого мира; live.sh теперь смотрит в неё
scripts/live-debug.sh --run run-live/<имя> hotswap <класс>   # правка сразу в копии, без перезапуска
scripts/live.sh fixture spirit-5 <файл> # этот мир становится фикстурой теста
scripts/test.sh unit --changed          # тест с фикстурой, затем коммит; scripts/dev-server.sh down
```

Основной сервер читается той же командой, если копии нет, менять его нельзя. Журнал и карта отвечают на вопрос
раньше брейкпоинта: сначала смотри на них. Карта основного сервера отстаёт до 5 минут (автосохранение),
карта копии — тоже до её сохранения. После выкладки главный агент запускает `scripts/live.sh check --wait 180`.

Агент поднимает **свою копию** живого мира, вживляет код в рантайме и сразу видит результат. Основной сервер для
этого не трогается: он остаётся для наблюдателей, игроков и публикации через `scripts/publish.sh`. Перезапускать
ради проверки идеи ничего не нужно; перезапуск копии — только если hotswap не может (см. ниже).

## Как устроено

| Слой | Решение | Почему |
|---|---|---|
| Где копия | ПК агента, каталог `<дерево>/run-live/<имя>` (в `.gitignore`) | 80 ГБ ОЗУ и Java 21; сервер domovoy с 11 ГБ (4 ГБ у основного) не тянет больше одной копии, поэтому копии там не запускаются |
| Основа | `.live-server` рядом с деревьями: `libraries`, моды, JBR SDK | общая база качается один раз и не попадает в git; копии берут её библиотеки |
| Мир | свежий `world-*.tar.zst` из `/opt/minecraft/backups/world` | снимок живой, но копия его не меняет; мир копии одноразовый |
| Мод | jar **своей** сборки дерева (`./gradlew assemble`) | две копии из двух веток не делят jar и видят разный код |
| Порты | свободные игра/REST/JDWP, на `127.0.0.1` | копия не видна в локалке и не конфликтует с основным сервером |
| JVM | JBR 21 SDK, `-XX:+AllowEnhancedClassRedefinition`, `--add-modules jdk.jshell,jdk.jdi` | JBR принимает новые методы и поля в redefine; JShell есть в SDK |
| Горячая замена | JDI `redefineClasses` по JDWP | работает с `TransformingClassLoader` NeoForge; новый класс доопределяется через `ClassLoader.defineClass` |
| Скрипты | `LiveShell` внедряется в загрузчик модов, внутри `jdk.jshell` | сниппет видит `MinecraftServer` и сервисы мода, компилируется без сборки мода |
| Брейкпоинты | `BreakpointRequest`, `SUSPEND_EVENT_THREAD` | останавливается только попавший поток; стек и переменные печатаются сразу |
| Владелец копии | аренда `owner.lease` (дерево, PID агента, срок) + heartbeat | копия живёт, пока жив агент; осиротевшая гасится и удаляется |

Клиент и мост — `scripts/live-debug/`; Gradle их не компилирует и в jar мода не кладёт.

## Публикация для наблюдателей

Копии не публикуются: у них свой jar, свой мир и свои порты. Если проверку нужно показать на **основном**
сервере (наблюдатели, клиенты), сборку ставит `scripts/publish.sh --temp -y` из дерева задачи: он обновляет
пакет клиента и страницу. Ручное копирование jar в `mods/` запрещено: пак и страница разойдутся, клиент не
пустит. Возврат на main — `scripts/publish.sh -y` из main.

## Копия: команды

| Команда | Что делает |
|---|---|
| `scripts/dev-server.sh up` | база (один раз), сборка jar, конфиги и мир из снимка, свободные порты, JBR+JDWP, `peaceful`, `forceload`, проверка REST |
| `scripts/dev-server.sh down [имя\|--tree]` | гасит копию по PID и удаляет `run-live/<имя>`; `--tree` — все копии дерева |
| `scripts/dev-server.sh status [имя]` | PID, порты, аренда, краткий ответ `/v1/bots` |
| `scripts/dev-server.sh list` | все копии дерева |
| `scripts/dev-server.sh setup` | только база: библиотеки и JBR SDK (≈280 МБ, медленный CDN тянется фрагментами) |

`up` требует живого процесса агента (`LIVE_DEV_OWNER_PID`; `opencode-task.sh` выставляет его сам). Если процесс
умер, `up` откажется. Предел копий на ПК — `LIVE_DEV_MAX` (по умолчанию 4, по числу исполнителей); при превышении `up` отказывает.

Копия поднимает игру на `127.0.0.1`, REST — на `127.0.0.1`, JDWP — на `127.0.0.1`; адреса пишутся в
`run-live/<имя>/debug.env`. `max-tick-time=-1` у копии: остановка на брейкпоинте не убивает процесс.

## Отладка в копии: команды

```
scripts/live-debug.sh --run run-live/<имя> init
scripts/live-debug.sh --run run-live/<имя> eval 'server.getPlayerList().getPlayerCount()'
scripts/live-debug.sh --run run-live/<имя> eval 'onServer(() -> server.getTickCount())'
scripts/live-debug.sh --run run-live/<имя> hotswap com.theminespirit.neoforge.PositionTrace
scripts/live-debug.sh --run run-live/<имя> hotswap com.theminespirit.neoforge.NewClass
scripts/live-debug.sh --run run-live/<имя> break com.theminespirit.neoforge.board.BoardLifecycle:24 -i --thread 'Server thread'
```

`--run` читает `debug.env` копии: адреса, классы, classpath. Замок основного сервера для копии не нужен — копия
принадлежит дереву. `hotswap` сначала делает `compileJava` (если не `--no-build`), затем:
- загруженный класс — `redefineClasses` (JBR разрешает новые методы и поля);
- незагруженный класс — `ClassLoader.defineClass` в загрузчик модов и подготовка.

`eval` выполняет сниппеты по очереди; `onServer` отдаёт работу потоку сервера и ждёт ответ. `break` без `-i`
печатает стек и локальные и продолжает; с `-i` — REPL (`stack`, `vars`, `up/down`, `cont`).

## Цикл

1. `scripts/dev-server.sh up` — один раз на заход (порты и мир свои).
2. Правится код дерева; `hotswap` (или `--no-build`, если уже собрано) — сразу видно в логе/мире копии.
3. `eval` для вопроса без сборки; `break` для состояния; наблюдение — `run-live/<имя>/logs/latest.log` и
   `http://127.0.0.1:<REST>/v1/bots`.
4. Правка переносится в мод, закрывается тестом, обычный коммит.
5. `scripts/dev-server.sh down` — копия гаснет, каталог удаляется. Основной сервер не трогается.

Если hotswap не может (например, миксин/трансформированный класс), перезапускается **копия**: `down` + `up`.
Основной сервер перезапускает только `scripts/publish.sh` по согласованию.

## Один агент и осиротевшие копии

- У копии есть `owner.lease`: дерево, PID процесса агента, срок. Heartbeat обновляет срок каждые 20 с; если дерево
  удалено или PID агента умер, heartbeat сам гасит java и запускает удаление каталога копии.
- `scripts/opencode-task.sh` в EXIT-ловушке вызывает `scripts/dev-server.sh down --tree`.
- `scripts/lead/orphan-sweep-win.sh` не считает java копии (`-Dlivedebug.copy=`) сиротой, пока аренда жива; для
  протухшей аренды/мёртвого владельца/удалённого дерева гасит процесс и удаляет каталог.
- Проверочный сценарий в `scripts/testing/check-orphan-sweep-win.sh`: живая копия не трогается, мёртвая и
  «дерево удалено» — гасятся.
- Замок `/opt/minecraft/debug.lock` остался для **основного** сервера; копии в нём не участвуют.

## Проверено вживую

- Две копии одновременно из двух деревьев (`wt-livedebug`, `wt-livedebug-b`): разные PID, порты, REST и миры; в
  логе A — `[pos-live-jbr] probe`, в логе B — `[pos-b]` (свой jar 0.1.2699), на основном сервере этих строк нет.
- JBR: в копии A добавлены новый статический метод и поле в `PositionTrace` и новый класс `LiveProbe`; `hotswap`
  принял это без перезапуска, лог копии сразу показал `[pos-live-jbr] probe`.
- `eval`/`break` в копии: `server.getPlayerList().getPlayerCount()` → 0;
  `onServer(() -> server.getTickCount())` → тики; брейкпоинт `BoardLifecycle:24` — стек и локальные, продолжение.
- Живой владелец убит: обе копии погашены heartbeat-сторожем, `run-live/<имя>` удалены, REST-порты закрыты.
- Поддельный тест сторожа: живая копия осталась, мёртвая и копия с удалённым деревом погашены.

## Ресурсы на копию

- ОЗУ: `-Xmx4G` (JBR); четыре копии — до 16 ГБ.
- Диск: мир ≈340 МБ, своя копия библиотек ≈177 МБ, моды/конфиги ≈20 МБ; база `.live-server` (библиотеки + JBR SDK
  ≈400 МБ) общая на все деревья.
- CPU: обычный тик сервера; четыре копии заметны, но ПК с 80 ГБ ОЗУ их держит.
- Порты: три свободных на копию (игра, REST, JDWP), только на `127.0.0.1`.

## Ограничения и риски

- Копии запускаются только на Windows-ПК агента. На domovoy — нет: там основной сервер и мало ОЗУ.
- JBR SDK скачивается один раз (`scripts/dev-server/fetch-jbr.py`), CDN медленный, качается фрагментами; база
  общая, повторный `up` её не качает.
- Копия делает снимок из `/opt/minecraft/backups/world`; основной сервер при этом только читается. Снимок,
  конфиги и моды — из живого сервера; сам живой мир копия не меняет.
- Мир копии одноразовый: `down` удаляет `run-live/<имя>` вместе с миром. Для сохранения — свой снимок до `down`.
- Аренда отслеживает PID процесса агента (MSYS). Если процесс убит `-9`, heartbeat/guard замечает это в пределах
  ~20 с; при падении ПК — по истечении срока аренды при следующем запуске сторожа.
- JDWP/REST копии — только `127.0.0.1`; на основном сервере JDWP 5005 остался с прошлой настройки, но основной
  для отладки не используется.
- Схему класса на **основном** сервере не меняем; JBR-расширение действует только в копии.
- `eval` идёт на потоке REST, а не сервера; для мира — `onServer`. Убийство клиента посреди вызова/брейкпоинта
  может оставить поток занятым — тогда перезапускается копия.

## Другие способы поднять качество (оценка)

| Идея | Что даёт | Цена |
|---|---|---|
| Снимок живого инцидента в фикстуру (`/v1/bots`, `/v1/board`, лог, позиции) | повторяемый вход в баг для GameTest/JUnit | один скрипт и формат; окупается на повторяющихся инцидентах |
| Воспроизведение инцидента из снимка мира в GameTest | проверка «до/после» на настоящем мире | копия мира и время прогона; для тяжёлых багов |
| Запись REST-вызовов агента и проигрывание на копии | регрессии протокола и поведения духов | нужен стенд; полезно для `/v1/*` |
| Автоперенос «hotswap → тест → напоминание» | не забыть тест после удачной живой правки | скрипт-обёртка цикла; следующий шаг |
