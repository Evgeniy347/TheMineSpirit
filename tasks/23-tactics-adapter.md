## Что должно получиться

Адаптер тактики — тонкий слой между миром и ядром `TacticsEngine`. Раз в `EVAL_INTERVAL_TICKS = 10` тиков (или по событию
«ударили») собирает `Situation` из мира, вызывает `TacticsEngine.step(situation, memory, nowTick)`, исполняет `TacticalOutcome`
через существующие примитивы: `Approach` для движения, ванильную атаку моба/духа для боя, `BlockBreaker` и постановку блоков
для баррикады, `SpiritEntity.setTarget()` для выбора цели. Режим боя (`CombatMode`) выставляется через `set_combat_mode`
(REST-команда стратега, чеклист 22). Leash ограничивает преследование: дух не уходит дальше `leashLeft` от якоря зоны.

Снятие фактов — порциями, с ограничением стоимости: без загрузки чанков (`getChunkNow`), без обходов мира в тике. Тест на
масштаб считает числа операций (чтения блоков, запросы сущностей), а не миллисекунды. Каждый способ отхода (`HOME`, `COVER`,
`KITE`, `WATER`, `BARRICADE`, `PILLAR`, `AWAY`) — отдельный GameTest на площадке `arena` 11×8×11, всё внутри площадки,
духи удаляются в конце, без `sleep`. Подлоги «что должно краснеть» — для каждого теста. Режимы боя и leash проверяются в
игре. Взаимодействие со слоем политик: если политика владеет тиком, тактика не вызывается, задача приостановлена.

## Общие точки с другими чеклистами (merge)

- `neoforge/SpiritEntity` — порядок тика: `chunkLoader.tick(); policies.tick(); if (!policies.isOverriding()) brain.tick();`
  добавить `tactics.tick()` между политиками и мозгом: `if (!policies.isOverriding()) { tactics.tick(); brain.tick(); }`.
  Чеклист 20 добавляет `SpiritPolicies`, этот — `TacticsService` рядом. Конфликт «оставить обе стороны» — политики выше.
- `neoforge/SpiritBrain` — `suspend()/resume()`: при приостановке политикой тактика тоже не тикает. `TacticsService` получает
  уведомление через `SpiritBrain.suspendReason()` или отдельный метод `tactics.suspend()`.
- `neoforge/Approach` — основной примитив для движения при отходе (`HOME`, `COVER`, `KITE`, `AWAY`). `Approach.begin(Vec3,
  arrival)` + `tick()` до `ARRIVED`/`TIMEOUT`.
- `neoforge/BlockBreaker` — баррикада (`BARRICADE`): ломает блоки для укрытия или ставит из инвентаря. Чеклист 10 даёт
  `begin()`/`tick()`/`cancel()`.
- `neoforge/LevelSafetyView` (чеклист 12) — чтение клеток для `EnvFacts` (`lavaNear`, `dropHeight`, `coverDistance`,
  `waterDistance`). Без загрузки чанков: только `cellAt(BlockCoord)` по загруженным чанкам.
- `core/policy/LayerArbiter` (чеклист 20) — порядок слоёв: `POLICY > TACTICS > STRATEGY > IDLE`. Адаптер тактики вызывается,
  только если политика не владеет тиком.
- `core/engine/{ScriptInstance,TaskRunner}` — приостановка: `suspend()` останавливает тактику, `resume()` возобновляет.
  Тайм-аут задачи не идёт во время приостановки.
- `neoforge/SpiritScripts` — `set_combat_mode` — отдельный скрипт из REST (чеклист 22). Адаптер тактики читает режим из
  `Orders.mode()`, который приходит из REST или локального конфига.

## Часть А — ядро адаптера (`core/tactics/adapter`, без Minecraft)

- [ ] 1. **`FactCollector`** — интерфейс снятия фактов: `collect(SituationContext ctx) → Situation`. `SituationContext` —
      входные данные (позиция дуга, список врагов, окружение, приказы, тики с урона/удара). Разделение на части: `SelfFacts`,
      `List<EnemyFact>`, `EnvFacts`, `Orders`, `ticksSinceHit`, `ticksSinceStrike`. Тесты (красными до реализации): таблица
      ≥ 10 строк (нет врагов, один враг, много врагов > 16 — сворачивание, враг вне радиуса видимости, день/ночь); свойство
      «враги отсортированы по (дистанция, тип, HP-доля, id)», «свыше `MAX_ENEMIES = 16` хвост сворачивается в запись "ещё n того
      же типа"».
- [ ] 2. **`ActionExecutor`** — интерфейс исполнения решений: `execute(TacticalOutcome outcome, SituationContext ctx) →
      ExecutionResult`. `ExecutionResult` — `MOVING(target)`, `ATTACKING(entity)`, `BUILDING(pos)`, `SHOOTING(entity)`,
      `IDLE`. Тесты: таблица ≥ 8 строк (FIGHT → `ATTACKING`, RETREAT+HOME → `MOVING`, RETREAT+BARRICADE → `BUILDING`,
      IGNORE → `IDLE`); свойство «каждое `TacticalOption` даёт ровно один `ExecutionResult`».
- [ ] 3. **`RetreatStateMachine`** — автомат состояний отхода: `IDLE → RETREATING(method) → HOLDING → IDLE`. Переходы:
      отход начинается при `RetreatMethod ≠ NONE`, удерживается `HOLD_TICKS` (предварительно 200), завершается при
      `TacticalOutcome.decision != RETREAT` или по таймауту. Тесты: таблица ≥ 10 строк (отход начинается, удерживается,
      прерывается атакой, таймаут); свойство «после `IDLE` следует только `RETREATING` или `IDLE`», «`HOLDING` не длится
      больше `HOLD_TICKS`».
- [ ] 4. **`TacticsConfig`** — конфигурация адаптера: `EVAL_INTERVAL_TICKS = 10` (предварительно), `MAX_ENEMIES = 16`,
      `FACT_RADIUS = 32` (радиус поиска врагов), `FACT_CHUNK_BUDGET = 64` (максимум чтений блоков на один цикл снятия фактов),
      `RETREAT_HOLD_TICKS = 200`. Загрузка из JSON `data/theminespirit/tactics/adapter.json`. Тесты: границы чисел,
      ошибки загрузки.

## Часть Б — адаптер в игре (`neoforge/tactics`)

- [ ] 5. **`WorldFactCollector`** — снятие фактов из мира порциями. `collect(SpiritEntity spirit) → Situation`: (а) `SelfFacts`
      — из полей духа (`hp`, `armor`, `inventory`, `position`), без чтений мира; (б) `List<EnemyFact>` — один запрос
      `getEntitiesOfClass` по враждебным мобам в радиусе `FACT_RADIUS = 32`, фильтр по `visible` (прямая видимость через
      `LevelSafetyView` — максимум `FACT_CHUNK_BUDGET` чтений); (в) `EnvFacts` — чтение клеток вокруг духа через
      `LevelSafetyView` (лава, обрыв, свет, дом, укрытие, вода) — порциями, не более `FACT_CHUNK_BUDGET` чтений за цикл;
      (г) `Orders` — из конфига/REST (режим, зона, подопечный). Без загрузки чанков: если клетка в незагруженном чанке —
      пропускать, не читать. Тесты (JUnit на мок-мире): таблица ≥ 12 строк (нет врагов, враг видим, враг невидим, лава рядом,
      обрыв, дом далеко, укрятие рядом, вода рядом); свойство «чтений блоков ≤ `FACT_CHUNK_BUDGET`», «запрос сущностей ≤ 1».
- [ ] 6. **`TacticsService`** — главный цикл адаптера. `tick()`: (1) если прошло < `EVAL_INTERVAL_TICKS` с последнего
      вызова — выйти; (2) собрать `Situation` через `WorldFactCollector`; (3) вызвать `TacticsEngine.step(situation, memory,
      nowTick)`; (4) исполнить `TacticalOutcome` через `ActionExecutor`; (5) обновить `memory`. Событийный вызов: при
      получении урона (`hurt`) — немедленный вызов `step()` (пропустить интервал). `TacticsService` живёт в `SpiritEntity`
      рядом с `SpiritBrain`. Тесты: таблица ≥ 8 строк (интервал не прошёл — вызова нет, интервал прошёл — вызов, урон —
      немедленный вызов); свойство «не более одного вызова `TacticsEngine.step` за 10 тиков».
- [ ] 7. **`CombatModeSet`** — выставление режима боя. `setCombatMode(CombatMode mode)`: (1) записать режим в `Orders.mode`;
      (2) вызвать `TacticsEngine.step()` с новым режимом; (3) обновить цель духа (`setTarget()` для агрессивного). Режимы:
      `PASSIVE` (не атаковать), `DEFENSIVE` (атаковать только при угрозе), `PROTECT` (защищать подопечного), `GUARD_AREA`
      (не уходить далеко от зоны), `AGGRESSIVE` (атаковать любого врага в радиусе). Тесты: таблица ≥ 10 строк (каждый режим,
      переключение режимов, режим без зоны); свойство «`AGGRESSIVE` всегда выставляет цель», «`PASSIVE` никогда не выставляет
      цель».
- [ ] 8. **`Leash`** — ограничение преследования. `leashLeft(spirit, target) → double`: `pursuitRadius − distance(anchor,
      target)`. Если `leashLeft ≤ 0` — не преследовать, отвлечься на безопасную точку. Якорь — центр зоны из `Orders` или
      позиция духа. Тесты: таблица ≥ 8 строк (цель внутри leash, цель на границе, цель за границей, нет зоны); свойство
      «при `leashLeft ≤ 0` цель не выбирается», «`leashLeft` не больше `pursuitRadius`».
- [ ] 9. **`RetreatExecutor`** — исполнение способов отхода через примитивы:
      - `HOME` — `Approach.begin(homePos, 1.0)` до `ARRIVED` или `TIMEOUT`.
      - `COVER` — `Approach.begin(coverPos, 1.0)` + проверка разрыва видимости (`LevelSafetyView`).
      - `KITE` — чередование `Approach.begin(awayPos)` и атаки (`setTarget()` + ванильный удар).
      - `WATER` — `Approach.begin(waterPos, 1.0)` + проверка, что враг не плавает.
      - `BARRICADE` — `BlockBreaker.begin(barricadePos)` + постановка блоков из инвентаря.
      - `PILLAR` — прыжок вверх + постановка блока под ноги (как `pillar_up`, но в бою).
      - `AWAY` — `Approach.begin(awayPos, 1.0)` без атаки.
      Тесты: таблица ≥ 12 строк (каждый способ, комбинации); свойство «каждый `RetreatMethod` даёт ровно один тип
      исполнения», «`BARRICADE` не ломает блоки вне инвентаря».
- [ ] 10. **`TacticsService` и политики** — взаимодействие со слоем политик. Если `SpiritPolicies.isOverriding()` —
       `TacticsService.tick()` не вызывается. При возобновлении (`RESUME_DELAY_TICKS = 10`) — пересборка фактов и вызов
      `step()`. Тесты: таблица ≥ 6 строк (политика активна — тактика не тикает, политика неактивна — тактика тикает,
      возобновление — вызов `step()`); свойство «при `isOverriding() = true` вызов `TacticsEngine.step` = 0».
- [ ] 11. **Сохранение состояния** — `TacticsMemory` и текущий `RetreatStateMachine` сохраняются в NBT духа
      (`SpiritTacticsStore`) и восстанавливаются при загрузке. Версионирование как у `SpiritTask`. Тесты: round-trip
      сохранения/восстановления, версия NBT, повреждённые данные — ошибка, а не тихий fallback.
- [ ] 12. **`TacticsTrace` — трассировка для логов и REST** — `TacticalOutcome.trace()` форматируется в текст
      (`Trace.explain()`), пишется в лог и доступен через REST (чеклист 22 добавляет поле в задачу). Тесты: формат
      трассировки, каждое поле `TacticalOutcome` присутствует.

## Стоимость в тике

- Снятие фактов: раз в 10 тиков, не более `FACT_CHUNK_BUDGET = 64` чтений блоков, не более 1 запроса сущностей радиуса 32.
- Вызов `TacticsEngine.step`: раз в 10 тиков или по событию урона.
- Исполнение действий: `Approach.tick()` — каждый тик до прибытия, `BlockBreaker.tick()` — каждый тик до поломки.
