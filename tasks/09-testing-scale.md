# 09 — тестирование в масштабе

Блок `todo.md` → «Тестирование в масштабе». Цель: тысячи осмысленных проверок, быстрый тир `./gradlew test`
укладывается в минуту. Перед работой прочитай `AGENTS.md`, `docs/TESTING.md`, `docs/CONVENTIONS.md`, `docs/GIT.md`.
Работа идёт в git worktree `/opt/minecraft/wt/09-testing` на ветке `task/09-testing`; коммить сюда, в main не сливай.

## Чеклист

- [ ] 1. **Параллельный прогон JUnit.** `src/test/resources/junit-platform.properties`: параллельное выполнение
      классов (`junit.jupiter.execution.parallel.*`), Gradle — `maxParallelForks` по числу ядер/2. Сторожа и тесты,
      которые читают общие файлы, не должны мешать друг другу — проверь. Замерь время `./gradlew test` до и после,
      числа — в отчёт и в `docs/TESTING.md`.
- [ ] 2. **Теги fast/slow.** Медленные тесты (свойства с большим числом прогонов, тесты на масштаб) — `@Tag("slow")`;
      `./gradlew test` гоняет всё, кроме slow; новая задача `./gradlew slowTest` — только slow; `check` зависит от
      обеих. Описать в `docs/TESTING.md` и в README → «Команды».
- [ ] 3. **Data-driven таблицы.** Один `@ParameterizedTest` × таблица кейсов вместо копий: сведи в таблицы
      близнецов (сейчас точно — четыре теста битого `pos` в `WorldObservationTests`), сериализацию наблюдения
      (кейсы: пусто, повторы предметов, сущности/контейнеры, крайние координаты), каталог скриптов (у каждого
      скрипта: id, обязательные параметры, границы — строка таблицы).
- [ ] 4. **Свойства-инварианты ядра** (jqwik), если их ещё нет: парсер плана на любом JSON бросает только
      `PlanValidationException` (не NPE/ClassCast/IndexOutOfBounds); round-trip JSON наблюдения для случайных
      наблюдений (включая повторы и пустые списки); hash не зависит от порядка всех списков; валидатор плана
      детерминирован (одинаковый вход → одинаковый результат или одинаковое исключение).
- [ ] 5. **Покрытие JaCoCo** — отчёт, а не гейт: `./gradlew jacocoTestReport` → `TestResults/coverage/`.
      Описать в `docs/TESTING.md`. Версия плагина — встроенная в Gradle (без выбора версий сверх этого).
- [ ] 6. В `todo.md` → «Тестирование в масштабе» отметить выполненное только после зелёного прогона.
- [ ] 7. `./gradlew test`, `./gradlew slowTest`, `./gradlew runGameTestServer` зелёные. Коммиты по пунктам.

## Замечания ревью (коммиты 7815f10..2911f60)

Проверено: изменяемого `static`-состояния, `System.setProperty`, записи общих файлов в `src/test` нет — параллельный
прогон классов сторожей и тестов не ломает. Таблицы `WorldObservationTests`/`ScriptCatalogTests` приняты.

- [x] R1. **Блокер: свойства jqwik не запускаются ни в одном тире.** jqwik не понимает `org.junit.jupiter.api.Tag`
      (у него свой `net.jqwik.api.Tag`). Факт из отчётов: в `TestResults/unit/xml` 256 тестов, **15 skipped**
      (все `@Property`: ChunkSquare 3, TaskRunner 1, WorldObservation 3, ResourceResolver 1, PlanParser 4,
      ScriptArgs 1, PlanValidatorRules 2); в `TestResults/slow/xml` у каждого файла `tests="0"`. Новые свойства п. 4
      не выполнялись ни разу; «slowTest зелёный» и «skipped 0» в отчёте неверны (AGENTS → «Отчёт»: число из прогона).
      Как надо: тег jqwik; `slowTest` падает, если выполнено 0 тестов (подсчёт в `afterSuite` или
      `failOnNoDiscoveredTests`). Доказательство в отчёте: `tests`/`skipped` по обоим каталогам xml.
- [x] R2. **Свойства перенесены в slow вопреки правилу.** TESTING → «Property-based»: «если свойство выросло по времени —
      уменьшай `tries`, а не переноси в slow». Быстрый тир занимал ~10 с из бюджета 60, замера времени свойств нет.
      Как надо: свойства остаются в `./gradlew test`; `slow` — только для теста с замеренным временем, которое не
      лезет в бюджет даже с уменьшенным `tries` (число — в отчёт). Сейчас таких нет — `slowTest` может быть пустым
      механизмом, но тогда без «зелёного» в отчёте.
- [x] R3. **Замер времени нечестный.** «10.3 с (219 тестов) → 9 с (256 тестов)»: разные наборы, а в «после» не
      выполнялись свойства (R1) — ускорение получено выключением тестов, а не параллелью. Чеклист п. 1 требовал числа

- [x] R4. **Процесс: пункты 1–6 одним коммитом** `2911f60` (build, свойства, таблицы, JaCoCo, README, todo). Нарушены

- [x] R5. **`todo.md` отмечен ложно.** «Детерминированный in-memory харнесс "фейковый мир"» — `[x] (частично)`, хотя

- [x] R6. **Свойства «любой JSON» почти не трогают валидатор.** `PlanParserProperties.parse_AnyJsonString_…` и

- [ ] R11. **База jqwik «на форк» — литерал, а не имя форка.** `build.gradle`: `".jqwik-database-fork-\${System.getProperty(...)}"`
      — `\$` экранирует подстановку, jqwik получает строку как есть: в корне worktree лежит файл
      `.jqwik-database-fork-${System.getProperty(org.gradle.test.worker)}` (и старый `.jqwik-database`). Номер форка в
      конфигурации Gradle и не вычислить — это свойство JVM-воркера. При `maxParallelForks = 1` отдельный файл не
      нужен: `jqwik.database=.jqwik-database` в `junit-platform.properties`, строку `systemProperty` убрать, в
      TESTING.md и `.gitignore` — без «отдельного файла на форк» (к нему вернуться вместе с форками). Заодно убрать
      мёртвую `junit.jupiter.execution.parallel.config.strategy=dynamic` при выключенной параллели.
      Проверка: после `./gradlew test --rerun-tasks` в корне только `.jqwik-database`.
