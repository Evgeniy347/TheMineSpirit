# 08 — замечания ревью к чеклистам 05, 06 и 07

Источник: ревью коммитов `a5a7c29..4f5b0e6` (05), `5a9b92d..8599598` (06) и `8f1b422..664de19` (07) от 2026-10-11. Перед работой прочитай
`AGENTS.md`, `docs/CONVENTIONS.md`, `docs/TESTING.md`, `docs/GIT.md`. Публикацию и перезапуск сервера не делать.

## Дефекты

- [ ] 1. **«/spirit goal … следуй за мной» не работает в игре.** `FallbackPlanner` подставляет в `follow.target`
      заглушку `"player"`, а `FollowScript` ищет игрока с именем «player» — на следующем тике задача падает
      «цель 'player' не найдена». GameTest `commandGoal_OnSelectedSpirit_StartsAndCancelsTask` этого не видит:
      проверяет `RUNNING` сразу после команды, до первого тика.
      Как надо: команда, выполненная игроком, передаёт в цель параметр `target` = имя этого игрока; заглушка
      `"player"` из правил fallback убирается. Цель «за мной» без игрока-источника (консоль, командный блок) —
      понятный отказ команды. GameTest (красный до исправления): мок-игрок выполняет `/spirit goal @e[…] следуй
      за мной`, через 40 тиков задача духа не `FAILED` и расстояние до игрока уменьшилось.
- [ ] 2. **`/spirit goal` применяется частично.** Цикл по духам ставит задачу одному, на следующем падает и
      возвращает 0 — первый уже работает, а команда сообщает о неудаче. Сначала спланировать для всех, потом
      запустить всем; при любой ошибке не запускать никому и назвать, у кого и почему. Тест на двух духов.
- [ ] 3. **Тест скана у незагруженных чанков ничего не доказывает.** `scan_Radius32NearUnloadedChunks_DoesNotLoadChunks`
      не проверяет, что в радиусе вообще были незагруженные чанки: если вокруг площадки всё загружено, тест
      зелёный при любом коде. `WorldScanner.Scan` отдаёт число пропущенных (незагруженных) чанков; тест требует
      `skippedChunks > 0` и неизменное число загруженных чанков. Подбери центр скана так, чтобы край
      загруженной области гарантированно попадал в радиус.
- [ ] 4. **Причина провала LLM теряется, если fallback тоже не справился.** `LlmPlanner.plan`: если
      `fallback.plan` бросает `UnplannableGoalException`, ошибка ИИ пропадает. Исходную ошибку ИИ добавить к
      исключению (`addSuppressed` или причина в тексте). Тест.

## Структура и стиль

- [ ] 5. **Сторож полных имён.** Главный агент добавил `guards/QualifiedNameGuardTests` (в дереве, не закоммичен):
      в коде — импорты, а не `net.minecraft.world.entity.EntityType.getKey(...)` / `com.mojang.brigadier.…`.
      Прогони, исправь все нарушения по проекту (сейчас точно есть: `SpiritCommands` — `CommandDispatcher`,
      `LiteralArgumentBuilder`, `CommandContext`, `BlockCoord`; `WorldScanner` — `EntityType`), докажи подлогом,
      что сторож краснеет, закоммить его вместе с исправлениями.
- [ ] 6. **`SpiritCommands` разросся:** регистрация + `spawn`, `observe`, `goal`, `status`, `cancel` в одном классе
      (CONVENTIONS → «Структура», независимые секции). Регистрация остаётся в `SpiritCommands`, обработчики —
      по классам (`SpiritSpawnCommand`, `SpiritObserveCommand`, `SpiritTaskCommands` для goal/status/cancel).
- [ ] 7. **`WorldScanner`:** комментарий о контейнерах (строки ~96–97) бессвязен («спектр этого же чанка
      отсчитывается…») — удалить или переписать одной ясной фразой; `chunk.getSections()` вызывается внутри
      цикла по `z` — вынести на уровень чанка.
- [ ] 8. **Источник плана — строка.** `PlanResult.source` с константами `SOURCE_LLM`/`SOURCE_FALLBACK` — это enum
      (`PlanSource`), как было с типом параметра.
- [ ] 9. **Умолчания снова в правилах fallback.** В шаблонах `FallbackPlanner` зашиты `count: 1`, `target: "hostile"`;
      `count` по умолчанию должен приходить из каталога (`ParamSpec.defaultValue`), как сделано в 4а чеклиста 06.
      Оставь в правилах только то, что действительно задаёт сама цель (фильтр скана).

## Замечания к 07 (коммиты 8f1b422, d8a6c54, 664de19)

- [ ] 11. **Билеты снимаются при остановке сервера.** `SpiritEntity.remove(reason)` вызывает `releaseChunkTickets()`
      при любой причине, включая `UNLOADED_TO_CHUNK`/`UNLOADED_WITH_PLAYER` — это и остановка сервера. После
      перезапуска чанк духа никто не держит: дух не тикает и не восстановит билеты, пока рядом не окажется
      игрок. Требование чеклиста 07 «после перезапуска чанки живых духов восстанавливаются» не выполнено.
      Снимать билеты только при `reason.shouldDestroy()` (убит, удалён) и `CHANGED_DIMENSION`.
- [ ] 12. **Проверка билетов при загрузке удаляет все.** `SpiritChunkTickets.validateTickets` удаляет билеты,
      если `level.getEntity(owner) == null`, но в момент проверки (загрузка мира) сущности ещё не загружены —
      удаляются все билеты всегда. Варианты: (а) в проверке оставлять все билеты — устаревших почти не бывает,
      т.к. убитый/удалённый дух снимает их сам (п. 11); (б) вести реестр живых духов в `SavedData` уровня и
      проверять по нему. Выбери (б), если он не дороже 1–2 классов; иначе (а) с тестом на то, что смерть духа
      снимает билеты.
      Тест логики решения — в `core` (какие билеты оставить при данных: владельцы билетов, известные живые
      духи); GameTest: `remove(UNLOADED_TO_CHUNK)` не снимает билеты, `discard()` снимает.
- [ ] 13. **`SpiritEntity` разрастается:** инвентарь, мозг задач, счётчик путей, слежение за чанками — несвязанные
      группы полей (CONVENTIONS → «Структура»). Слежение за чанками (`trackedCenter`/`trackedRadius`/
      `trackedChunks`, `updateChunkTickets`, `releaseChunkTickets`) — в отдельный класс `SpiritChunkLoader`,
      которым владеет сущность.
