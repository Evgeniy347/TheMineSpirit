## INC-34 `acquire charcoal ×8` — невыполнимая цель, вечный цикл — 10:02–10:12
- Духи: spirit-1 (f58b83b6), spirit-2 (3ac95237), spirit-3 (1fe55e4f).
- Что видно (факты): лог 10:11–10:12, каждые ~10–20 с:
  «провалил задачу 'acquire': не удалось добыть 'charcoal' ×8: в инвентаре при старте 0, из сундуков запланировано 0,
  сейчас в инвентаре 0, пополнено 0, попыток 3; причина: добыто 0 из 8; … подходящих блоков в радиусе 16 не осталось;
  состояние FAILED; пауза 200 тиков, тот же скрипт не повторяется». В `latest.log` 60 строк с `charcoal`.
  При этом `torch:craft_torches` на доске требовал `{coal:2}` и `missing {}` — обычный уголь был (у spirit-1 7 шт.),
  и задание позже стало `DONE`: факелы сделаны из угля. `acquire charcoal ×8` продолжает ставиться снова и снова.
- Почему это тупик: `charcoal` (древесный уголь) не встречается блоком в мире — он получается переплавкой брёвен в
  печи. `acquire` ищет блоки в радиусе 16 и физически не может его «добыть»; путь «бревно → печь → уголь» не
  строится. У задачи нет ни одного сценария завершения.
- «Ушла в блок?» — да, по факту: не в `BLOCKED` доски (тикет `CRAFT_TORCHES` уже `DONE`), а в вечный цикл
  FAILED → пауза 200 тиков → снова `acquire`. Дух занят этим вместо полезной работы; заодно этой причиной
  «не хватает charcoal» падают посторонние задания доски (протечка причины, повтор INC-24/31).
- Ожидалось: для факелов брать `coal` из `requiredItems`/инвентаря/передачи; `charcoal` — только если есть печь и
  брёвна, и через `smelt`, а не `acquire`; при отсутствии пути — один отказ и `BLOCKED`, без повторов.
- Вмешательство: нет (только наблюдение и описание).
- Гипотеза причины: планировщик — `acquire` не знает рецептов (древесный уголь — крафт/переплавка), а план выбирает
  `charcoal` при доступном `coal`.
- Предложение: `acquire` должен уметь синтез по рецепту (smelt/craft) и выбирать ближайший источник (`coal` >
  `charcoal` > брёвна+печь); невыполнимую потребность помечать `BLOCKED` и не переставлять каждые 200 тиков.

- Гипотеза причины: ночь — все занимаются `DEFEND/COMBAT/REST`; первые шаги жёстко требуют `oak_*`; кейса
