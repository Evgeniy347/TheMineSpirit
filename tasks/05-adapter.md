# 05 — адаптер NeoForge: нагрузка на тик, goto/follow, команды

Источник: ревью кода от 2026-10-11. Перед работой прочитай `AGENTS.md`, `docs/CONVENTIONS.md`
(«Производительность»), `docs/TESTING.md` (GameTest). Публикацию на сервер и перезапуск не делать.

## Находки

1. **Скан грузит тик и чанки.** `WorldScanner.observe` с радиусом 32 обходит 65³ ≈ 275 тыс. позиций и для
   каждой вызывает `getBlockState` и `getBlockEntity` (для контейнера — `getBlockState` второй раз).
   На незагруженном чанке `getBlockState` синхронно грузит чанк — фриз сервера.
2. **Путь пересчитывается каждый тик.** `GotoScript` и `FollowScript` вызывают `navigation.moveTo` в каждом
   тике — поиск пути 20 раз в секунду на духа.
3. **goto сдаётся через 15 секунд при любом расстоянии.** `GotoScript.MAX_TICKS = 300` не зависит от дистанции:
   дальняя цель всегда `FAILED`.
4. **Команды и тесты, отмеченные в todo как готовые, отсутствуют.** В `/spirit` есть `spawn` и `observe`, но нет
   постановки цели, статуса и отмены. GameTest на сопровождение игрока (`follow`) нет.

## Чеклист

- [ ] 1. Скан: позиции в незагруженных чанках пропускаются (без загрузки чанка), контейнеры берутся из
      block entities загруженных чанков в радиусе, без второго `getBlockState`. Тест на масштаб в `core`
      невозможен — сделай счётчик операций в адаптере доступным GameTest (например, результат скана несёт
      число просмотренных позиций) и GameTest: радиус 32 у края загруженной области не грузит новые чанки.
- [ ] 2. goto/follow: новый путь строится, только если цель сместилась больше чем на 1 блок или навигация
      закончилась/застряла. GameTest: число вызовов построения пути за 100 тиков следования за неподвижной
      целью — не больше 2.
- [ ] 3. goto: тайм-аут зависит от расстояния (например, 40 тиков на блок + запас) и есть детект застревания
      (позиция не менялась N тиков → `FAILED` с причиной). Константы — в одном месте.
- [ ] 3а. Скрипт сам называет причину провала: `ScriptInstance.failureReason()` (по умолчанию пусто), её
      подхватывает `ScriptExecutor` вместо общего «завершился с ошибкой». goto: «не дошёл до (x, y, z) за N тиков»,
      «застрял в (x, y, z)»; follow: «цель '<имя>' не найдена». Замечание ревью чеклиста 02.
- [ ] 4. `/spirit goal <id> <текст>`, `/spirit status <id>`, `/spirit cancel <id>` — через `FallbackPlanner`
      (LLM не трогать). Планировщик получает каталог `SpiritScripts.catalogFor(spirit)` (только реализованные
      скрипты), а не полный `CoreScripts.defaultCatalog()` — иначе план «руби дерево» пройдёт валидацию и упадёт
      при исполнении. Статус показывает итог последней задачи с причиной провала (`SpiritBrain`). Духа выбирать селектором сущности. Сообщения игроку — на русском.
- [ ] 5. GameTest: дух с `follow` догоняет неподвижного «игрока» (мок-игрок GameTest) до радиуса удержания.
- [ ] 6. `./gradlew test` и `./gradlew runGameTestServer` зелёные. Коммиты по пунктам.
