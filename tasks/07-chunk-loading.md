# 07 — дух держит чанки загруженными, как игрок

Решение пользователя от 2026-10-11: дух полноценно нагружает чанки вокруг себя, как игрок. Мобы в Minecraft
живут только в загруженных и «тикающих» чанках; без этого дух, ушедший от игрока дальше зоны симуляции
(~100–160 блоков), замирает.

Перед работой прочитай `AGENTS.md`, `docs/CONVENTIONS.md` («Быстрый путь», «Производительность»),
`docs/TESTING.md`. Публикацию на сервер и перезапуск не делать.

## Что должно получиться

- Вокруг каждого живого духа принудительно загружен и тикает квадрат чанков радиуса R, где R по умолчанию —
  simulation distance сервера (как у игрока). R можно переопределить в серверном конфиге мода.
- Когда дух переходит границу чанка, набор сдвигается: добавляются только новые чанки, снимаются только
  ушедшие. Пересчёт — только при смене чанка, не каждый тик.
- Дух умер, удалён, выгружен или ушёл в другое измерение — все его чанки освобождены.
- После перезапуска сервера чанки живых духов восстанавливаются, а билеты исчезнувших духов отбрасываются.

## Чеклист

- [x] 1. `core`: чистая функция смены набора чанков: `ChunkSquare.diff(oldCenter, newCenter, radius)` →
      `(toAdd, toRemove)`; координаты чанков — core-тип, без классов Minecraft. JUnit + свойства:
      размер квадрата `(2R+1)²`; `old − remove + add = new`; при совпадении центров diff пустой; при сдвиге на
      1 чанк добавляется и снимается ровно `2R+1`.
- [x] 2. Адаптер: NeoForge `TicketController` с id `theminespirit:spirit`, регистрация в
      `RegisterTicketControllersEvent` (шина мода), владелец билета — сущность духа, `ticking = true`.
      Обратный вызов проверки при загрузке мира отбрасывает билеты духов, которых больше нет.
- [x] 3. `SpiritEntity`: при первом тике на сервере — загрузить квадрат; при смене чанка — применить diff;
      при `remove`/смерти/смене измерения — снять все свои билеты. Логика решения — в `core`,
      в сущности только применение.
- [x] 4. Радиус: серверный конфиг мода `spirit.chunkLoadingRadius`, по умолчанию `-1` = simulation distance
      сервера; явное значение — от 1 до 32. Описать параметр в README → «Команды» или отдельной строкой.
- [x] 5. `goto` не ограничивается по дальности (только границы мира из чеклиста 03). Убедись, что тайм-аут
      `goto` (≈ 40 тиков на блок, чеклист 05) работает и для дальних целей. Проверено: `GotoParams`
      ограничен только `WORLD_HORIZONTAL_LIMIT`/`WORLD_Y_*`, а `GotoTuning.timeoutTicks` пропорционален
      расстоянию (`40·distance + 200`).
- [x] 6. GameTest: (а) у заспавненного духа чанки радиуса R принудительно загружены; (б) после переноса духа
      в соседний чанк набор сдвинулся на один ряд; (в) после `discard()` у духа не осталось билетов.
- [x] 7. Тест на масштаб в `core`: последовательность переходов на N чанков даёт ровно N·(2R+1) добавлений
      и столько же снятий — считать операции, не время.
- [x] 8. `./gradlew test` и `./gradlew runGameTestServer` зелёные. Коммиты: ядро (`feat:`), билеты в адаптере
      (`feat:`), конфиг (`feat:`).

## Отчёт

Коммиты: `8f1b422` (ядро — квадрат/сдвиг), `d8a6c54` (конфиг радиуса + README), `664de19` (билеты,
`SpiritEntity`, GameTest).

Тесты: `./gradlew test` — 214 тестов, 0 падений (в т.ч. `ChunkSquareTests` 7, `ChunkSquareProperties` 3,
`ChunkLoadingRadiusTests` 4). `./gradlew runGameTestServer` — All 10 required tests passed, в т.ч.
`chunkLoading_SpiritSpawnedMovedAndDiscarded_KeepsTickingSquare`.

R по умолчанию = simulation distance сервера. В `/opt/minecraft/server/server.properties`
`simulation-distance=10`, значит один дух держит `(2·10+1)² = 441` чанк. Для тестового `GameTestServer`
simulation distance = 0, поэтому `ChunkLoadingRadius.effective` поднимает радиус до минимума 1 (вырожденный
R=0 не даёт духу тикать после перехода в соседний чанк).

Замечания для ревью:
- `Time budget`: сдвиг квадрата на соседний чанк становится видимым только после завершения
  `entityTickingChunkFuture` соседнего чанка (≈20 тиков в GameTest); в проде при R≥1 дух остаётся внутри
  уже тикающего квадрата, но на самой границе возможна краткая задержка тика.
- Открытый риск: колбэк `validateTickets` на старте мира (`level.getEntity(owner) == null`) может снять
  билеты живого духа до его загрузки; живые духи вдали от игроков при этом не перезагрузятся
  (курица-и-яйцо). Решение отложено на ревью (канонический паттерн NeoForge против отдельного
  `SavedData`-реестра живых духов).
