## Решения, принятые самостоятельно

- Работа сервера `wt/reach-planner` переносится вручную по смыслу (ReachPlanner, его тесты и свойства), интерфейс мира
  переименую — в main `BlockSupport` уже класс правила опоры. Сервер не трогаю.
- Формат: файл `schematics/<id>.txt`; слои снизу вверх, `y0` первым; первая строка слоя — фронт (z=0, сторона входа до
  поворота), столбцы слева направо = +X; легенда — один символ; `.` — клетка обязана быть воздухом (стройка её
  очищает, если защита разрешает, иначе отказ с причиной), ` ` — не трогать; состояние `block[k=v,…]`, `facing=auto`
  для факела (по опоре). Двухчастные блоки пишутся одной буквой в обеих клетках (дверь — в двух слоях, кровать —
  в двух клетках): половина/изголовье определяются сами; материалы — один предмет на пару.
- Метаданные пресета (name, type, stage, level, requires, вход) и исключения сторожей (`rule` + `reason`) — в шапке
  текстового файла; `presets.json` остаётся только списком id для горячей перезагрузки; устаревшее исключение
  по-прежнему валит тест.
- Сторожа только усиливаются: + кровать целиком внутри, вход на уровне пола, внутренность достижима от двери,
  факел/светильник на опоре. Пороги и исключения ради зелёного не трогаю.
