# 03 — валидация плана: типы, диапазоны, белые списки

Источник: ревью кода от 2026-10-11. Перед работой прочитай `AGENTS.md`, `docs/CONVENTIONS.md`
(«Структура»: проверки типа в одном месте, «Ошибки»), `docs/TESTING.md`, `docs/API.md`.

## Находки

1. **`enum` не проверяется.** `PlanParser.convertParam` для `TYPE_ENUM` принимает любую строку: у `ParamSpec`
   нет списка допустимых значений.
2. **Нет диапазонов.** У `ParamSpec` нет min/max. `docs/API.md` обещает `count` 1..256, а план с `count: -5`
   или `wait ticks: 2_000_000_000` проходит. Свойство `parse_waitScriptWithAnyTicks…` закрепляет этот дефект.
3. **`repeat.times` без верхней границы.** Лимиты глубины и числа узлов есть, а `repeat` на 2^31 итераций
   проходит — по сути бесконечный цикл от ИИ.
4. **`condition.check` не по белому списку.** Скрипты проверяются по каталогу при разборе, проверки
   условий — только во время исполнения; параметры условий не валидируются вообще.
5. **Два пути в обход валидатора.** `FallbackPlanner` и `ResourceResolver` собирают `TaskNode` напрямую,
   минуя `PlanParser`, — их планы никто не проверяет (например, `count` из параметров цели любого типа).
6. **Тип параметра — строка-константа.** `ParamSpec.type` — `String` с `TYPE_*`, отсюда `switch` по строкам с
   `default`-веткой и второй слой проверок типов в `ScriptArgs` (из-за того, что `int` приходит то `Integer`,
   то `Long`). Это одно правило в двух местах.
7. **Каталог обещает то, чего нет.** `CoreScripts` описывает 31 скрипт, реализованы два (`goto`, `follow`).
   ИИ получит в каталоге `chop_tree`, план пройдёт валидацию и упадёт при исполнении «неизвестный скрипт».
8. Радиус скана описан дважды: `ScanRadius.MIN/MAX` и (без границ) параметр `radius` скрипта `scan`.

## Чеклист

- [ ] 1. `ParamSpec.type` → `enum ParamType` (`INT`, `DOUBLE`, `STRING`, `STRING_LIST`, `BOOL`, `ENUM`);
      преобразование JSON-значения — метод самого типа или одна таблица, без `switch` по строкам.
      `INT` всегда даёт `Integer` (значение вне `int` — ошибка валидации). `ScriptArgs` упрощается до чтения
      уже типизированных значений.
- [ ] 2. В `ParamSpec`: `min`/`max` для чисел, `values` для `ENUM`, необязательный `defaultValue`.
      Валидатор проверяет диапазон и допустимые значения, сообщение называет скрипт, параметр, границы
      и полученное значение.
- [ ] 3. Значения границ — константы в ОДНОМ месте (класс лимитов каталога), со ссылкой на источник в имени
      или в `docs/API.md`: `count` 1..256 (из API.md), радиус скана — из `ScanRadius`, `repeat.times` 1..64,
      `wait.ticks` 1..6000, `follow.radius` 0..16, координаты `y` −64..319, `x`/`z` ±30 000 000. Лимиты `repeat`, `wait`, `follow` утверждены пользователем
      2026-10-11 (AGENTS.md → «Решения пользователя»).
- [ ] 4. Валидатор над деревом: `PlanValidator.validate(TaskNode, ScriptCatalog, ConditionCatalog)`.
      `PlanParser` = JSON → `TaskNode` → `PlanValidator`. Планы `FallbackPlanner` и `ResourceResolver` проходят
      тот же валидатор (тест: fallback-цель с `count: "пять"` → `PlanValidationException`, а не план).
- [ ] 5. `ConditionCatalog` (как `ScriptCatalog`): имя проверки + параметры; `condition.check` и его параметры
      валидируются при разборе. Пока проверок нет — каталог пуст, и любой `condition` отклоняется с понятным
      сообщением.
- [ ] 6. Каталог для ИИ = только реализованные скрипты: `ScriptCatalog.restrictedTo(Set<String> ids)`;
      адаптер строит каталог из ключей своего `ScriptRegistry`. GameTest: каждый id реестра адаптера есть
      в `CoreScripts.defaultCatalog()` (иначе скрипт нельзя вызвать из плана).
- [ ] 7. Тесты: data-driven таблица (`@ParameterizedTest`) — по строке на каждое правило валидации
      (тип, диапазон снизу/сверху, enum, лишний параметр, отсутствующий обязательный, repeat вне границ,
      неизвестная проверка). Свойство: любое значение вне диапазона отклоняется, внутри — принимается.
      Свойство `parse_waitScriptWithAnyTicks…` переписать под диапазон.
- [ ] 8. `docs/API.md` → описание `capabilities` и параметров совпадает с тем, что отдаёт каталог (min/max/values/default).
- [ ] 9. `./gradlew test` и `./gradlew runGameTestServer` зелёные. Коммиты по частям: тип параметра (`refactor:`),
      диапазоны и enum (`fix:`), валидатор над деревом (`fix:`), каталог проверок (`feat:`), каталог для ИИ (`fix:`).
