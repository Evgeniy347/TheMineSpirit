# Изменения формата, данных и кода; новые сторожа

Опора на то, что уже есть: текстовые схемы и `SchematicTextParser`, сторожа `SchematicRules`, `PresetLibrary`
с `requires`/`planned`, поворот и якорь по двери (`DemoPlacement`: начало считается от клетки входа), стройка с места
(`ReachPlanner`, `SchematicSite` — уже ставит недостающее и очищает `.`), задания доски `BUILD_*`,
`REPAIR_BUILDING`, `REPAIR_FENCE`, `RELOCATE_BUILDING`, `LIGHTING`, скрипты `light_area`, `build_fence`, `fill`.

## Данные

1. **`schematics/buildings.json` — каталог семей** вместо зашитого в Java `DemoBuildings`: `id`, название, тип,
   участок `W×D`, уровни `[{level, scheme, stage}]`, что уровень даёт (`beds`, `chests`, `stations`) — для нужд.
   `/spirit demo <семья> [уровень]` и `upgrade a b` читают каталог; новая постройка не требует правки кода.
2. **`town_layout.json`** — шаблон поселения (слоты, улицы, граница, plan.md). **`stages.json`** — состав этапов.
   **`settlement_demand.json`** — правила нужды (repair.md). **`repair.json`** — игнорируемые состояния и блоки.
3. Таблица `stage → материалы` для сторожа палитры (style.md).

## Формат схемы — дополнения

4. **Мягкая клетка**: суффикс `~` в легенде (`'v': poppy ~`) — ставится при стройке, ремонт её не требует
   (цветы, посевы, саженцы, ковры). Сторож: мягкими бывают только блоки из списка `repair.json`.
5. **Составные предметы**: `potted_<цветок>` = горшок + цветок, нажимная плита на заборе, свеча — материалы
   разворачиваются в предметы; постановка одним действием — **упрощение, вопрос 14**.
6. **Этажи**: необязательное `floors: [1, 5]` (уровни пола) — сторож высоты меряет каждый этаж отдельно.
7. Позже, не в этом блоке: подмена породы дерева (`@wood`) по биому.

## Новые сторожа схем (`SchematicRules`, по правилу «сторож, а не текст»)

| Сторож | Что проверяет | Почему |
|---|---|---|
| `hanging_support` | фонарь `hanging=true` и цепь держатся за блок сверху; люк-ставень, знамя, лестница — за стену | сейчас опора — только снизу или сбоку, фонарь под навесом будет «висящим в воздухе» |
| `reachable_inside` | от клетки входа пешком (шаг ≤ 1, лестница, ступеньки) достижимы каждая кровать, сундук, станок и каждый этаж | мебель не перегораживает проход, второй этаж не замурован |
| `level_continuity` | у уровня N+1 той же семьи: тот же вход-якорь; сундуки, кровати, станки уровня N на тех же местах или перечислены в `moves:` | улучшение на месте не теряет содержимое сундуков и не ломает жильё |
| `plot_fit` | габарит каждого уровня + крыльцо помещаются в участок семьи | резерв участка верен, сосед не задет |
| `stage_palette` | материалы уровня доступны на его этапе | уровень 1 не требует фонарей и кирпича |
| `roof_overhang` (мягкий, только жильё и ремесло) | крыша выступает за стены хотя бы с двух сторон | «коробка без свеса» не проходит |
| `spacious` | у жилья площадь пола на кровать ≥ 12 клеток, свободный проход ширины 2 от входа вглубь | правило «просторно» машиной |

Каждый новый сторож — с тестом на шаблон (фикстуры в `src/test/resources/schematic-rules/`), как нынешние.

## Код (новый пакет `core/settlement`, чистый, без Minecraft)

| Класс | Ответственность |
|---|---|
| `BuildingCatalog` | загрузка `buildings.json`, семьи, уровни, проверка ссылок на схемы |
| `TownLayout` | шаблон: слоты, улицы, граница; поворот на 4 стороны |
| `TownPlanner` | шаблон + карта высот + препятствия + нужды → план (чистая функция, тестируется) |
| `TownPlan`, `Plot` | состояние плана, статусы слотов, проверка правок стратега |
| `StreetPlan` | полосы улиц и троп по уровню улиц → задания `fill`-типа |
| `WallPlan` | линия границы → сегменты (прямые, углы-башни, ворота) → записи реестра |
| `StageRules`, `DemandRules` | этап поселения и выбор следующей стройки по данным |
| `BuildingRegistry` | записи реестра, индекс «участок → постройка» |
| `RepairAudit` | разница мир/схема по абстракции чтения клеток → список правок (тест без мира) |

`neoforge`: сохранение плана и реестра в мире, зонд рельефа (карта высот, вода, постройки игрока по меткам духов),
обход проверки по бюджету тика, команды `/spirit plan show|build|reserve`, REST `GET /v1/town`,
`POST /v1/town/edits`. `FirstStepsRunner` берёт координаты заданий из плана, а не «у дома».

## Инструменты автора

- (отменено решением 12: вместо PNG — `/spirit demo city`) `scripts/schematic.sh render` → PNG-изометрия:
  смотрит стиль в Telegram без запуска игры (вопрос 12).
- `scripts/schematic.sh diff <a> <b>` — разница уровней (что добавить/убрать) и проверка `level_continuity`.
- Генератор крыши по плану этажа (двускатная, вальма, свес, карниз) — заготовка слоёв для автора, результат
  правится руками и коммитится текстом; в моде генератора нет.
