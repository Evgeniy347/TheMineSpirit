# Порядок реализации блоками

Принцип: видимый результат раньше, массовое производство схем — только после того, как владелец принял стиль.
Каждый блок — законченный кусок с тестами и одним-двумя коммитами; объём — оценка (S ≤ 1 ч, M 2–3 ч, L 5–8 ч).
Схемы разных семей не пересекаются по файлам — блоки библиотеки делятся между исполнителями по семьям.

## Б1. Каталог и витрина стиля (L) — первым

- `buildings.json` вместо `DemoBuildings`, `/spirit demo` читает каталог, `upgrade a b` для любой семьи.
- Новые сторожа: `hanging_support`, `reachable_inside`, `level_continuity`, `plot_fit`, `stage_palette` (format.md).
- Демо `/spirit demo city [1..5]` (решение 12): духи одновременно строят все постройки этапа; табличка у сундука.
- Схемы-витрина по эскизам: `family_house` 1–4, `player_house` 1–4, `plaza` 1–3, `well` 2, `lamp` 2–3.
- Итог для владельца: `/spirit demo city 1..5` и `/spirit demo family_house upgrade 1 4` в игре.
- **Точка согласования**: владелец смотрит и правит стиль; дальше блоки библиотеки идут в принятом стиле.

## Б2. Ограждение, ворота, улицы, свет (M–L)

- `WallPlan`: линия границы → сегменты 8, углы-башни, ворота и малые ворота; схемы `wall` 1–3, `gate` 1–3,
  `wicket` 1–2, `archer_tower` 1; уровень стены по сегментам.
- `StreetPlan`: полосы главной, боковой, кольцевой улиц и троп; уровни `street` 1–2; фонари по шагу.
- Демо: `/spirit demo wall <ширина> <глубина> [уровень]` — дух огораживает прямоугольник с воротами и улицей.
- Существующие `BUILD_FENCE` и `LIGHTING` начинают брать линию из `WallPlan` (а не из `fence` 9×9 у дома).

## Б3. План поселения v1 (L) — поселение раскладывается само

- `town_layout.json` (шаблон «крест с кольцом»), `TownPlanner` (поворот по рельефу, слоты, препятствия, граница),
  `TownPlan` в мире, `BuildingRegistry`.
- Зонд рельефа и препятствий (вода, постройки игрока по меткам духов), подготовка участка (срез/подсыпка).
- `FirstStepsRunner` и задания доски ставят постройки в слоты плана; `SettlementFacts` — из реестра.
- Команды `/spirit plan show` (текстовая карта в чат), `reserve`; REST `GET /v1/town`.
- Итог: на новом месте духи сами проходят этап 0 — расчистка, сундуки, шахта, забор по линии, свет, первый
  каменный дом в центре, площадь 1, пашня — по плану, а не в кучу у дома.

## Б4. Библиотека этапов 1–2 (L, параллельно по семьям)

`barracks` 1–2, `storage` — новая оболочка 1–4, `barn` 1–2, `field` 1–3, `orchard` 1–2, `pen` 4 (+кормушки 1–3),
`lumber_yard` 1–2, `workshop` 1–2, `forge` 1–2, `bakery` 1–2, `apiary` 1, `fish_dock` 1, `kennel` 1, `stable` 1,
`mine_entrance` 2–4 (todo «доска v2»). У каждой семьи — показ в `demo city` и проверка сторожами; приёмка владельцем пачкой.

## Б5. Нужды, этапы, улучшения на месте (M–L)

- `stages.json`, `StageRules`; `settlement_demand.json`, `DemandRules` (каждое число в тесте).
- Улучшение на месте через доску: материалы по разнице схем, `UPGRADING`, кровати до сноса старых.
- Стена растёт по уровням сегмент за сегментом от ворот.

## Б6. Ремонт (M)

- `RepairAudit` (чистый, тест без мира), обход по бюджету тика, события (взрыв, пожар, сломанная дверь).
- `REPAIR_BUILDING` / `REPAIR_FENCE` из реестра, приоритеты в `board.json`, прикрытие при враге рядом.
- Блоки игрока не трогаются; журнал расхождений.

## Б7. Пересмотр плана и стратег (M)

- Ежедневная проверка, строка в чат, перенос (`RELOCATE_BUILDING`), рост границы (если выбран рост кольцами).
- REST `POST /v1/town/edits` с проверкой плана; описание в `docs/api/` и `docs/STRATEGIST.md`.

## Б8. Библиотека этапов 3–4 (L, параллельно)

`town_hall`, `tavern`, `infirmary`, `library`, `training_yard`, `trading_post`, `alchemy`, `weaver`, `enchant_room` —
оболочка 1–2 и уровень 3, высшие уровни остальных семей, `wall` 4 и ров, `gate` 4, `archer_tower` 2–3,
`street` 3–4, `lamp` 4, `plaza` 2 (если не сделан в Б1), `bridge`.

## Б9. Дальние постройки (M)

`outpost` 1–3, `lighthouse`, `pier`, `fish_dock` 2 — у ресурсов и воды, вне основного плана (свои мини-планы).

## Риски

- **Объём схем** (~110 файлов): главный риск качества у дешёвых исполнителей. Защита — сторожа, показ в `demo city` на каждую
  схему, приёмка пачками; витрина Б1 — образец для подражания.
- **Скорость стройки** больших построек (особняк, склад 4, стена 160×160): тест демо меряет результат, а не время;
  потолки тайм-аутов — с запасом, стройка на нескольких духов (`BuildSquad` уже есть).
- **Рельеф**: неровные миры дают много земляных работ — пределы среза/подсыпки в данных (вопрос 16).
- **Производительность** обхода ремонта — бюджет клеток на тик в данных, тест на предел.
