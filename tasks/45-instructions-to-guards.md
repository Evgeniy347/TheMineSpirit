# Чеклист 45. Инструкции → сторожа и тесты (владелец 19.10)

Принцип (AGENTS.md): система не даёт написать плохой код, а не уговаривает. Каждый пункт — **удалить из инструкции
и написать сторож/тест**. Сторож — в `src/test/java/com/theminespirit/guards/`, сообщение: правило, цена, как надо;
у сторожа-шаблона — тест на шаблон (подложное нарушение находится). Нарушения, найденные сторожем в текущем коде,
исправляются в том же блоке (или — явный список исключений в данных с причиной; устаревшее исключение валит сторож).
После сторожа абзац в документе удаляется или сжимается до строки-ссылки.

## Мёртвый код (владелец 19.10)

14. [x] **DeadCodeGuard** (`src/main/java`, кроме пакета `gametest`): класс, метод или поле production-кода, на которые
    нет ссылок из другого production-кода, — нарушение. Ссылки из `src/test/java` и из `gametest` **не считаются**
    (код, который нужен только тестам, — мёртвый). Точки входа не нарушение: `@Mod`, `@EventBusSubscriber`,
    `@SubscribeEvent`, `@Override` (методы Minecraft/NeoForge/JDK), регистрация в реестрах, `record`-компоненты,
    читаемые Jackson, `main`, `META-INF/services`. Остальное — явный список исключений в данных с причиной
    (например, «задача todo: …»); устаревшее исключение валит сторож. Новых зависимостей не добавлять (версии —
    решение пользователя): разбор — по исходникам (имена объявлений и ссылки), допускаются ложноотрицательные
    срабатывания из-за совпадения имён, но не ложноположительные. Найденный мёртвый код удалить вместе с тестами,
    которые проверяют только его; если код — заготовка под открытую задачу todo/tasks, — исключение со ссылкой на задачу.
