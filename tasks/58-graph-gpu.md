# 58. Подбор весов графа на видеокарте

Решение владельца 27.10: расчёт графа — в матричной форме (сделано в Java: `core/board/graph/GraphFlow`,
`GraphPlanner`), подбор коэффициентов — на GPU (Python, PyTorch, GTX 1060 6 ГБ на ПК).

## Источник истины

Java-код, который работает в игре. Python — только ускоритель поиска весов. Выгрузка: `./gradlew graphExport` →
`TestResults/graph-export/graph.json` (граф) и `conformance.json` (200 состояний поселения с заданиями Java:
id, priority, feasible, chance, просьбы стратегу). Python-модель **обязана** совпадать с Java на этих случаях:
priority ±1, feasible и набор заданий — точно (тест `tools/graph-gpu/test_conformance.py`). Найденные веса
возвращаются в `board/graph.json` и проверяются Java-перебором (`./gradlew mutationTest`, только с согласия
владельца).

## Что сделать (`tools/graph-gpu/`)

1. `graph_model.py` — загрузка graph.json, построение системы `p = r + A·p` для состояния по правилам
   `GraphPlanner` (корни: нехватка Xmin·P·S·K, набор духа по этапу, постройки этапа, склад, триггеры, стадо, события;
   связи: потребность → доступные пути с весом, путь → недостающие входы/needs/инструмент/постройка с decay,
   группа → источники членов, инструмент → пути уровней выше текущего; выше набора — «ждёт случая» без связей;
   местные надбавки: готовая постройка, перенаселение, рёбра со знаком), решение Якоби, шкала
   `100·(1 − e^(−s/100))`, выполнимость заданий.
2. `test_conformance.py` — сверка с `conformance.json` (pytest).
3. `sim_gpu.py` — пакетная симуляция на torch: B миров × набор весов, духи берут разные выполнимые задания по
   приоритету, мир меняется (выход пути, расход, постройка, инструмент), этапы 1–3; метрика — шагов до конца этапа 3
   (застрял — штраф).
4. `search.py` — поиск весов (эволюционный, CMA-ES или аналог) по метрике на нескольких стартовых мирах и сидах;
   границы весов ±50 % от текущих; вывод — лучшие веса JSON и отчёт шагов (до/после).
5. README в каталоге: как ставить (версии — решает владелец), как запускать, что выгружать из Java.

## Ограничения

- Не дублировать решения тактики и доски — только модель графа и простая симуляция.
- Веса меняются только в `board/graph.json`; код Java не трогать.
