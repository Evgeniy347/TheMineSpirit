# 04 — наблюдение: стабильный hash и контракт JSON

Источник: ревью кода от 2026-10-11. Перед работой прочитай `AGENTS.md`, `docs/CONVENTIONS.md`
(«Структура»), `docs/TESTING.md`, `docs/API.md` → `POST /v1/bots/{id}/observe`.

## Находки

1. **hash зависит от порядка слотов.** `WorldScanner` кладёт в инвентарь запись на каждый слот, поэтому один
   предмет встречается несколько раз. `WorldObservation` сортирует только по имени предмета, сортировка
   стабильная — записи одного предмета остаются в порядке слотов. Две стопки `oak_log` (64 и 5) в разных слотах
   дают разный hash для одного и того же инвентаря. Свойство `hash_inventoryOrderChanged…` этого не ловит:
   генерирует только разные имена (`item_0`, `item_1`, …).
   То же для сущностей: порядок по типу и блок-позиции, при совпадении — порядок входа.
2. **hash меняется каждый тик.** В каноническую форму входит `tick` и точное `distance` сущностей (double,
   дрожит при движении внутри блока). Сообщение GameTest говорит, что «по hash bridge сравнивает картины мира», —
   с тиком внутри любые два наблюдения различны.
3. **JSON не совпадает с контрактом.** `docs/API.md`: поля `bot`, `pos`, `hash`. `WorldObservation.toJson()`
   (Jackson по компонентам record) отдаёт `botId`, `position` и не отдаёт `hash`.
4. **Один record — три работы.** `WorldObservation` хранит данные, сериализует JSON и считает hash.
5. **Имена.** `InventoryEntry` используется и для инвентаря, и для подсчёта блоков в радиусе. Core-тип `BlockPos`
   совпадает с именем класса Minecraft, поэтому в адаптере и GameTest он пишется полным именем пакета.

## Чеклист

- [ ] 1. Свойство (красное до исправления): одинаковый мультимножественный инвентарь (повторяющиеся предметы,
      любой порядок слотов) → одинаковый hash. Генератор должен порождать повторы имён.
- [ ] 2. Исправь: наблюдение хранит инвентарь агрегированным по предмету (сумма количеств), порядок
      сущностей и контейнеров — полный (тай-брейк по всем полям). Тест на агрегацию.
- [ ] 3. hash описывает картину мира: без `tick` и без `distance` (она выводится из позиций). Тест: два
      наблюдения одного мира в разные тики — один hash; сдвиг сущности на блок — другой hash.
- [ ] 4. JSON по контракту `docs/API.md` (`bot`, `tick`, `pos`, `radius`, `inventory`, `blocks`, `entities`,
      `containers`, `hash`). Контрактный тест с эталонной строкой JSON. Round-trip остаётся.
- [ ] 5. Раздели обязанности: данные — `WorldObservation`; JSON — отдельный класс (например, `ObservationJson`);
      hash — отдельный (`ObservationHash`). Jackson остаётся в `core` (решение главного агента: формат JSON —
      часть контракта ядра, `docs/research/README.md` поправлен).
- [ ] 6. Переименуй `InventoryEntry` → `ItemCount`, core `BlockPos` → `BlockCoord`; убери полные имена пакетов
      в адаптере и GameTest.
- [ ] 7. `./gradlew test` и `./gradlew runGameTestServer` зелёные. Коммиты: hash (`fix:`), JSON-контракт (`fix:`),
