# 02 — устойчивость движка задач

Источник: ревью кода от 2026-10-11. Перед работой прочитай `AGENTS.md`, `docs/CONVENTIONS.md`
(«Структура», «Ошибки»), `docs/TESTING.md`.

## Находки

1. **Исключение из скрипта роняет сервер.** `TaskRunner.ScriptExecutor.advance` ловит только
   `UnknownScriptException`. Если `ScriptFactory.create` (например, `GotoParams.from` с неверным параметром)
   или `ScriptInstance.tick` бросит `RuntimeException`, оно пройдёт через `SpiritBrain.tick` в
   `SpiritEntity.customServerAiStep`, а исключение в тике сущности — это краш сервера («Ticking entity»).
   То же для `ConditionEvaluator.test` в `ConditionExecutor`.
2. **Отмена не доходит до скрипта.** `ScriptInstance` умеет только `tick()`; `ScriptExecutor` не переопределяет
   `cancel()`. Сейчас это прикрыто тем, что `SpiritBrain` останавливает навигацию, но скрипт, который держит
   ресурс (занятый блок, предмет в руке, резерв на складе), не узнает об отмене.
3. **Дублирование.** `SequenceExecutor`, `RepeatExecutor`, `FallbackExecutor`, `ConditionExecutor` повторяют
   одну схему «текущий дочерний исполнитель»: поле `current`, одинаковые `currentScript()` и `cancel()`.
   `SequenceExecutor.advance` и `RepeatExecutor.advance` почти совпадают. В `FallbackExecutor` дважды одна и та
   же строка сообщения. `TaskRunner.java` — 475 строк, шесть классов в одном файле.

## Замечания ревью (коммиты 051966b, 43dd282, 31c44c1)

- [ ] R1. `ScriptExecutor.advance`: при исключении из `instance.tick()` живой экземпляр остаётся в поле, и его
      `cancel()` не вызывается — задача `FAILED`, а дух продолжает идти по навигации. При исключении: вызвать
      `cancel()` живого экземпляра (исключение из самого `cancel()` — добавить как suppressed к исходному),
      обнулить поле. Тест (красный до исправления): скрипт бросает из `tick()` → его `cancel()` вызван ровно один раз.
- [ ] R2. Причина провала теряет тип и стек: `"скрипт 'x' упал: " + getMessage()` даёт «упал: null» для
      исключения без сообщения. Формат: `скрипт '<id>' упал: <ИмяКлассаИсключения>: <сообщение>`.
      `TaskRunner` отдаёт и само исключение: `failureCause(): Optional<Throwable>`. То же для условий.
      Тест: исключение без сообщения → причина содержит имя класса, `failureCause` — то самое исключение.
- [ ] R3. Тихий провал в адаптере: `SpiritBrain.tick` при завершении задачи обнуляет `runner`, причина
      провала теряется — её нет ни в логе, ни в `status()`. `SpiritBrain` хранит итог последней задачи
      (статус + причина) и отдаёт его наружу (понадобится `/spirit status` в чеклисте 05); при `FAILED` пишет
      в лог WARN с id духа, причиной и стеком `failureCause`. GameTest: goto в недостижимую точку → после
      провала статус духа `FAILED` с причиной, а не «нет задачи».
- [ ] R4. `./gradlew test` и `./gradlew runGameTestServer` зелёные; коммиты `fix:` по замечаниям.
