# 22 — Агент-стратег: внешний ИИ на opencode ставит задачи духам по REST

Источник: `todo.md` → «Управление и ИИ» (LLM раз в несколько минут формирует глобальные цели для каждого духа; тактика
детерминированная, LLM — только стратегия; критичное решает тактика без ожидания LLM), «LLM-протокол» (структурированное
наблюдение в промпт, lease/latest-wins), «P5 — ИИ-планировщик» (валидация ответа, отказ невалидного плана, fallback при
недоступности ИИ, тесты с фейковым транспортом); `AGENTS.md` → «Решения пользователя» (стратег — внешний ИИ-агент, который ходит в
мод по REST; мод сам LLM не вызывает; сначала агент на opencode с бесплатными моделями, затем на Sonnet 5.5; REST внутри мода,
**без авторизации**, сеть доверенная); `docs/API.md` (контракт, формат плана); `tasks/14-rest-server.md`, `tasks/15-rest-tasks.md`
(что и когда появится в моде); `docs/EXECUTOR-MODELS.md` (какие бесплатные модели работают). Идеи — `docs/research/llm-agents-skills.md`:
`DecisionSession` (latest-wins: устаревший ответ отбрасывается), anti-loop `RunMemory`, критик `{success, critique}` как «недавние
решения» в промпте, наблюдение как данные в границах (риск prompt injection), «постусловие ≠ завершение шага». Код сторонних
проектов не копируется.

Перед работой прочитай `AGENTS.md`, `docs/CONVENTIONS.md` (Ошибки — тихий fallback запрещён; Файлы и кодировки; Временные файлы),
`docs/TESTING.md` («тест обязан уметь краснеть», подлоги), `docs/GIT.md`, `docs/API.md` целиком, `docs/EXECUTOR-MODELS.md`,
`scripts/opencode-task.sh` (надзор: `PROVIDER_PATTERN`, молчание модели, проба провайдера, `failures.log`) и
`scripts/testing/{check-opencode-task.sh,fake-opencode.sh}` (образец регрессионной проверки). Публикацию мода, перезапуск сервера и
**включение боевого режима против настоящего сервера не делать** — только по согласованию с пользователем.

**Зависимости.** Чеклист не трогает Java и не ждёт других чеклистов: всё строится и проверяется на фейковом REST. Настоящий мод
понадобится только для ручной проверки (раздел «Этапы»). `scripts/opencode-task.sh` не меняется.

## Что должно получиться

Отдельная программа (не мод), которая живёт на сервере и раз в несколько минут решает, чем заняться простаивающим духам:

- **Каталог `agents/strategist/`** (код и промпт — в репозитории) и **рабочий каталог `STRATEGIST_HOME`** (по умолчанию
  `/opt/minecraft/strategist`, вне репозитория: журнал, состояние, логи, песочница opencode; в git не попадает, содержит ники — не
  публиковать). Python 3 только стандартной библиотекой (на сервере 3.12, зависимостей и `pip` нет).
- **Цикл** раз в `INTERVAL` (300 с, предварительно; допустимо 60..3600): `GET /v1/capabilities` (раз в цикл) → `GET /v1/bots` → для
  каждого `idle` духа `POST /v1/bots/{id}/observe` → промпт → решение модели → проверка → `POST /v1/bots/{id}/tasks` → отслеживание
  `GET /v1/tasks/{id}` каждые 10 с (предварительно) до `succeeded|failed|cancelled`, тайм-аут задачи 30 мин (предварительно) —
  затем `DELETE`. Занятых (`busy`) и мёртвых духов не трогает никогда: задачи игрока и `/spirit goal` важнее стратега.
- **Мозг подменяем.** Агент вызывает «мозг» как функцию «промпт → текст». `opencode` — `opencode run -m <модель> --format json` в
  песочнице; `command` — любая команда (stdin: JSON `{system, user, model}`, stdout: ответ), через неё позже подключается Sonnet 5.5.
  Модель по умолчанию — лучшая бесплатная из `docs/EXECUTOR-MODELS.md` (сейчас `opencode/longcat-2.5-preview-free`; запасная
  `opencode/nemotron-3-ultra-free`), переключается `STRATEGIST_MODEL` / `STRATEGIST_MODEL_FALLBACK` без правки кода. Дешёвый
  детерминированный слой вокруг модели (проверка, лимиты, журнал) решает, что вообще можно отправить в мир.
- **Ответ модели** — один JSON: `{"reason":"…","goal":"…","plan":{…}}` или `{"reason":"…","skip":true}` (ничего не делать — законное
  решение). Формат узла `plan` — «Формат плана» из `docs/API.md`; промпт берёт этот раздел из файла, а не копирует.
- **Безопасность по построению.** Модель запускается в песочнице с запретом всех инструментов opencode (нет `--auto`, `bash`/`edit`/
  `webfetch` запрещены): даже при prompt injection из имён сущностей она может только вернуть текст. Отправляются только скрипты из
  `GET /v1/capabilities` **и** из белого списка `policy.json` (стартово: `goto, scan, collect_drops, chop_tree, mine_vein, gather, till,
  plant_crop, harvest_crop, bone_meal, wait`; хозяин расширяет), параметры — по схеме каталога, план ≤ 32 узлов и ≤ 8 шагов в корне
  (предварительно). Режим `STRATEGIST_MODE`: `dry` (по умолчанию: всё, кроме `POST tasks`, решения только в журнал) или `live`.
- **Журнал решений** `journal.jsonl`: по строке на событие (`cycle_start, bot_skipped, observed, decision, rejected, posted, task_state,
  task_done, brain_failure, alert`), поля `schema, ts, cycle, bot, model, prompt_sha, reason, plan, request_id, task_id, outcome`;
  ответ модели в журнале — до 4 КиБ; ротация 10 МиБ × 5 файлов (предварительно). Состояние `state.json` (активные задачи, счётчики,
  кулдауны) пишется атомарно и позволяет пережить рестарт без повторных задач.

## Защита от зацикливания и спама (всё предварительно)

| Правило | Значение |
|---|---|
| задач на одного духа в час | ≤ 6; пауза между задачами одного духа ≥ 60 с |
| вызовов модели в час, всего | ≤ 30; на духа за цикл — 1 (+1 повтор после отказа проверки) |
| один и тот же план (отпечаток `goal`+`plan`) после `failed/cancelled` | кулдаун 30 мин |
| подряд провалов задач одного духа | 3 → дух на паузе 30 мин, строка `alert` |
| `hash` наблюдения не изменился с прошлого решения | модель не вызывается («мир не менялся») |
| провайдер модели недоступен | пауза между циклами ×2 до 30 мин; вместо полного промпта — проба «ответь OK» |
| запросов к REST | ≤ 5/с у клиента; `429` — ждать `Retry-After` (лимитер мода: ведро 40, 20/с) |
| файл `STRATEGIST_HOME/PAUSE` существует | новых задач нет, отслеживание продолжается |
| дух стал `busy` между наблюдением и отправкой | решение отбрасывается (latest-wins), перед `POST` — свежий `GET /v1/bots/{id}` |
| `request_id` | `uuid5(бот, цикл, отпечаток)` — повтор после обрыва не создаёт вторую задачу |
