# 06 — планировщики: тихий fallback, ложные совпадения, количества рецептов

Источник: ревью кода от 2026-10-11. Перед работой прочитай `AGENTS.md`, `docs/CONVENTIONS.md`
(«Ошибки», «Структура»), `docs/TESTING.md`. Выполнять после `03-plan-validation.md`.

## Находки

1. **Тихий fallback.** `LlmPlanner.plan` ловит `LlmException`/`PlanValidationException` и молча отдаёт план
   запасного планировщика: нигде не видно, что ИИ ошибся и почему. Это нарушение «тихий fallback — авария».
2. **Ложные совпадения ключевых слов.** `FallbackPlanner` ищет подстроки: «поверни налево» содержит «верни»
   → `return_home`; «трудно» содержит «руд» → добыча руды. Порядок правил решает исход («убей зомби у дерева»
   → рубка).
3. **Две копии одного правила.** `chopPlan` и `minePlan` — одна схема (scan с фильтром + скрипт с count).
   Правила и числа (радиус 32, дефолты) — в коде, а не данными.
4. **Неверные количества в рецептах.** `ResourceResolver.craftPlan` умножает ингредиенты на число нужных
   предметов, считая, что крафт даёт 1 штуку. 1 бревно даёт 4 доски: для 8 досок резолвер добудет 8 брёвен
   вместо 2. `ingredient.count() * count` может переполниться.

## Чеклист

- [ ] 1. `Planner.plan` возвращает результат с источником и причиной (`PlanResult(TaskNode plan, String source,
      Optional<String> fallbackReason)` или аналог). `LlmPlanner` при ошибке ИИ отдаёт план fallback **с причиной**.
      Тест: невалидный ответ ИИ → план fallback и причина с текстом ошибки валидации.
- [ ] 2. `FallbackPlanner`: сопоставление по словам (токены, начало слова), а не по подстроке. Тесты (красные
      до исправления): «поверни налево» и «трудная задача» не распознаются; «руби дерево», «иди за мной» —
      распознаются. При нескольких совпадениях — понятное правило приоритета и тест на него.
- [ ] 3. Правила fallback — данные (таблица «основы слов → шаблон плана»), шаблон scan+скрипт — одна
      реализация для рубки и добычи.
- [ ] 4. `ResourceKnowledge` сообщает выход рецепта (`outputCount`); резолвер считает число крафтов как
      ⌈нужно / выход⌉ и умножает ингредиенты на число крафтов. Переполнение — `UnplannableGoalException`
      с понятным текстом. Тесты: 8 досок → 2 бревна; 1 доска → 1 бревно.
- [ ] 4а. Значения по умолчанию — из каталога (перенесено из ревью чеклиста 03, R3). `PlanValidator` подставляет
      `ParamSpec.defaultValue` для отсутствующего необязательного параметра, план после валидации содержит его явно.
      Удалить дубли умолчаний: `FollowParams.DEFAULT_RADIUS`, `getOrDefault(..., 32)` и прочие в `FallbackPlanner`.
      `docs/API.md` уже обещает `default` в capabilities — после пункта это должно быть правдой.
      Тест: `follow` без `radius` → в плане `radius` равен значению по умолчанию из каталога.
- [ ] 5. `UnplannableGoalException` несёт предмет, на котором оборвалась цепочка, отдельным полем `item()`.
      `ResourceResolverProperties` берёт предмет из поля, а не разбирает кавычки в тексте сообщения
      (замечание ревью задачи 01: разбор текста ломается от любой правки формулировки).
- [ ] 6. `./gradlew test` зелёный. Коммиты по пунктам.
